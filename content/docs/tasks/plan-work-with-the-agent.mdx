Chats are private: only the person who starts one sees it. To plan in one you
need:

- A host serving the workspace with the harness you want to plan with. The chat
  runs on the same hosts as any other run. See
  [Install a host](/docs/hosts/run-a-host).
- To let the agent read your code, the GitHub App connected to the workspace.
  See [Connect GitHub to a workspace](/docs/integrations/connect-github).

## Start a chat

<Steps>
<Step>

Open your team in the sidebar and select **Agent**.

</Step>
<Step>

In the composer that reads **What do you want to plan?**, open the agent
picker, which names the harness, and choose the harness under **Harness**. For
a model other than the harness's default, choose it under **Model**. If the
harness offers an effort, choose it under **Effort** the same way.

</Step>
<Step>

Below the composer, select **No repositories** and tick the repositories the
agent should have checked out. The list shows what the GitHub App can see; it
reads "No repositories to choose from" when GitHub is not connected.

</Step>
<Step>

Write what you want to work on and press Enter.

</Step>
</Steps>

The harness and repositories are fixed for the chat once it starts. To change
them, start another chat. The model and effort can change with each reply.

To plan from what earlier runs did, start from their traces instead: open
**Insights** in the team sidebar, then the **Traces** tab. Tick the traces to
discuss (a chat takes up to 20), and select **Discuss with the agent**. The Agent page opens with the
traces attached to a new chat's composer; carry on from the second step.

To have the agent propose a change to a station from its runs, start from the
station: see [Improve a station from its runs](/docs/improvement/improve-a-station-from-its-runs).

While the chat shows **The agent is working…**, you can stop it with the
**Stop** button. Reply in the box that reads **Reply…**; to add files, select
**+**, or drop or paste them on the box. To answer with another model or
effort, choose it in the agent picker before you send.

## Create the tasks it proposes

The agent's proposals appear in the thread as cards titled **Waiting for your
approval**. Read the task under **Task**, the line and station under
**Station**, and the description under **Details**.

- To accept a proposal, select **Create task**. The task is created at the
  back of the proposed station, with you as its assignee, and a run starts on
  it at once if the station has a harness. Select the title under **Task** to
  open it.
- To decline it, select **Dismiss**.
- To take the title and description elsewhere, select the copy icon.

If **Station** reads "Station deleted", the station was removed from the line
after the agent proposed it, and **Create task** is unavailable. See
[Proposals](/docs/reference/app/tasks-runs-and-the-inbox#proposals) for each
card title.
