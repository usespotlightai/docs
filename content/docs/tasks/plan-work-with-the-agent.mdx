Chats are private: only the person who starts one sees it. To plan in one you
need:

- A host serving the workspace with the harness you want to plan with. The chat
  runs on the same hosts as any other run. See
  [Install a host](/docs/hosts/run-a-host).
- To let the agent read your code, the GitHub App connected to the workspace.
  See [Connect GitHub to a workspace](/docs/integrations/connect-github).

## Start a chat

<Steps>
<Step>

Open your team in the sidebar and select **Agent**.

</Step>
<Step>

Below the composer that reads **What are we planning?**, choose the harness,
and the model and effort if you want something other than **Default model**.

</Step>
<Step>

Under **Repositories**, tick the repositories the agent should have checked
out. The list shows what the GitHub App can see; it reads "No repositories to
choose from" when GitHub is not connected.

</Step>
<Step>

Write what you want to work on and press Enter.

</Step>
</Steps>

The harness, model and repositories are fixed for the chat once it starts. To
change them, start another chat.

To plan from what earlier runs did, start from their traces instead: open
**Insights** in the team sidebar, then the **Traces** tab. Tick the traces to
discuss (a chat takes up to 20), and select **Discuss with the agent**. The Agent page opens with the
traces attached to a new chat's composer; carry on from the second step.

To have the agent propose a change to a station from its runs, start from the
station: see [Improve a station from its runs](/docs/improvement/improve-a-station-from-its-runs).

While the chat shows **The agent is working…**, you can stop it with the
**Stop** button. Reply in the box that reads **Reply…**; attachments work there
too.

## Create the tasks it proposes

The agent's proposals appear in the thread as **Proposed task:** rows, each
with its state.

Select a proposal to open it in a side panel, which shows the line and station
it is proposed for, the title and the description. Select **Create task** to
accept it, or **Dismiss** to decline it.

An accepted task is created at the back of the proposed station, with you as
its assignee. If that station has a harness, a run starts on the task at once.
The proposal then reads **Task created**.

**Create task** is unavailable when the proposal reads "A station that is
gone": the station was removed from the line after the agent proposed it.
