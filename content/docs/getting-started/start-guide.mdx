In this tutorial we will give Spotlight its first piece of work and watch an AI
agent pick it up.

In Spotlight, a piece of work is a task. A task moves through a series of
steps, such as triage, then writing a spec, then building it. Spotlight calls
the series a line and each step a station. At most stations an AI coding agent
does the work, then passes the task on to the next station or stops to ask us a
question.

Spotlight keeps track of the work, and the agents run on a computer we
provide. Here that will be our own computer, which Spotlight calls a host.

By the end we will have:

- created a workspace
- set up our computer so agents can run on it
- given a task to the first station of a line, and answered the question its
  agent asks us

We use Spotlight at `app.usespotlight.ai`. On a
[self-hosted Spotlight](/docs/reference/glossary#spotlight-address), use the
deployment's address wherever this tutorial shows `app.usespotlight.ai`.

## Before we start

We need:

- A GitHub account. Spotlight signs us in with GitHub.
- A Mac or Linux computer with Docker Desktop, OrbStack, Colima or Podman
  installed and running. Spotlight runs each agent inside a container, so the
  agent can't reach the rest of the computer.
- An Anthropic API key. The agents in this tutorial are Claude Code, and they
  need the key to use Claude.

## Create a workspace

A workspace holds everything Spotlight knows about our organisation: its
people, its teams, and each team's lines and tasks.

<Steps>
<Step>

Open [app.usespotlight.ai](https://app.usespotlight.ai) and click
**Continue with GitHub**. Approve the sign-in on GitHub.

</Step>
<Step>

Spotlight asks us to name the workspace. Notice that the URL field fills
itself in from the name. Click **Continue**.

</Step>
<Step>

Spotlight asks for a first team, a group of people who share lines and an
inbox. Name it and click **Create workspace**.

</Step>
</Steps>

Spotlight opens the **Inbox**. This is where anything that needs a person
lands, such as an agent's question. It already holds one item: **Set up your
team**. Open it. It lists two steps, **Install the GitHub App** and **Run a
harness**, and neither has a check mark yet. A harness is the AI coding tool an
agent runs, Claude Code in this tutorial, and the second step is about giving
it somewhere to run. We will come back to it.

In the sidebar, under **Your teams**, expand our team, then **Lines**. The
team already has two lines. **Delivery** takes a request from Triage through to
Code Review, and **Review** looks over pull requests. We will use Delivery.

## Let our computer take work from Spotlight

Spotlight hands work to a
[pool](/docs/administration/ways-in-pools-trusts-and-tokens), a group of
computers that all prove who they are with the same secret token. We will
create a pool with only our computer in it.

<Steps>
<Step>

In Spotlight, click **Runners** in the sidebar. This page lists the computers
that run agents for the workspace. It has none yet.

</Step>
<Step>

Under **Pool name**, leave `my-computer` and click **Create pool**. The page
now shows a command that installs Spotlight on a computer, with the pool's
token already in it. Spotlight shows the token only this once, so keep the
page open.

</Step>
</Steps>

## Start running agents on our computer

<Steps>
<Step>

Open a terminal. The agents use Claude, so they need our Anthropic key. Save it
in the file Spotlight reads on our computer when it starts:

```bash
mkdir -p ~/.spotlight
echo 'ANTHROPIC_API_KEY=<your Anthropic key>' >> ~/.spotlight/sandbox.env
chmod 600 ~/.spotlight/sandbox.env
```

The commands print nothing.

</Step>
<Step>

On the **Runners** page, click **Copy command** and run it in the terminal. It
looks like this, with the pool's token in place of `<pool token>`:

```bash
curl -fsSL https://app.usespotlight.ai/api/install.sh | SPOTLIGHT_TOKEN=<pool token> sh
```

The command downloads the `spotlight` program and the container image agents
run in, then sets the program to keep running in the background. The image
download takes a few minutes. The last line reads:

```text
spotlight host: serving https://app.usespotlight.ai: this machine shows on the workspace's Runners page once it reports
```

If it stops with `no container runtime answered`, Docker, or whichever of the
tools above we use, isn't running. Start it and run the command again.

</Step>
<Step>

Watch the **Runners** page. Within a minute our computer appears in its own
row, with **Pool my-computer** under **Serves**. Under **Harnesses** are the
logos of the coding tools it can run, Claude Code among them. Its status reads
**Idle**: it is connected and waiting for work.

</Step>
<Step>

Go back to **Inbox** and open **Set up your team**. **Run a harness** now has a
check mark: our computer is ready to take work.

</Step>
</Steps>

## Give Triage a task

Triage is the first station of Delivery. Its agent reads a new task and decides
what it needs next.

<Steps>
<Step>

Open **Delivery**. The board lists the stations where agents work, one below
the other: Triage, Spec, Implementation and Code Review. Each is a section with
its tasks underneath. New tasks start in the backlog, where they wait until
someone moves them on. Click **Backlog** at the top of the board to see only
the backlog.

</Step>
<Step>

Click **+** beside **Backlog**. In **Task title**, enter:

```text
Write a welcome note for new teammates
```

In **Add description…**, enter:

```text
Write a short welcome note for the people joining our team next week.
Only I know who they are and what they'll work on.
```

Click **Create task**.

The task needs no code. It leaves out something only we know, and when a
request leaves something open, Triage's instructions tell its agent to ask a
person instead of guessing.

</Step>
<Step>

The task waits in the backlog. Notice that nothing happens to it there: no
agent picks up a task until it reaches a station where agents work.

Point at the task and tick the box that appears beside it. A bar appears at
the bottom of the board. Click **Move to Triage**.

</Step>
<Step>

Click **Active**. The task now stands at **Triage**, marked **In progress**: an
agent is working on it. On the **Runners** page, our computer reads **Running 1
of 1**, one agent running out of the one it has room for.

</Step>
</Steps>

## Watch the agent work

<Steps>
<Step>

Click the task's title to open it. Under **Activity** there is one row, for
Triage. Each row is a run: one session in which an agent works on the task at
a station. Click it.

</Step>
<Step>

At the top is what the agent was told, folded to its first few lines. Click it
to see all of Triage's instructions, followed by our task. Below that, the
agent's steps appear as it works, each labelled with what it did, such as
**Read** or **Thought**. For the first few moments nothing appears, while our
computer starts a fresh container for the agent.

</Step>
<Step>

When the agent finishes, its note appears under what it was told. The note
ends with a question for us, such as who the new teammates are and what they
will work on, and the run now reads **Waiting for you**.

If the agent passed the task on to Spec instead of asking, its note says why
it thought nothing was left open. Open the task, choose **Backlog** in the
station field under **Properties**, then choose **Triage** in the same field.

</Step>
</Steps>

Go back to the board. The task is still at Triage, now marked **Awaiting
review**. It stays there until we answer.

## Answer the agent

<Steps>
<Step>

Open **Inbox**. There is a new item, **Write a welcome note for new
teammates**, in bold because we haven't read it. Open it. It shows the same
run, ending with the agent's question.

</Step>
<Step>

In the box at the bottom that reads **Reply…**, enter:

```text
Two designers, Sam and Priya, who will work on the mobile app. This task was only a test, so there's no need to pass it on.
```

Press Enter.

</Step>
<Step>

The agent works again, and the item shows its steps as they happen. When they
stop, its new note shows how it used our answer.

</Step>
</Steps>

## Close the task

We have seen what we came to see, so we will close the task ourselves before it
goes any further down the line.

<Steps>
<Step>

Open the task from the board. On the right, under **Properties**, the first
field shows which station the task is at. The panel shows only when the window
is wide enough.

</Step>
<Step>

Choose **Completed** from it. If an agent is still working on the task,
Spotlight stops it. The task moves to Completed, the end of the line, and the
**Runners** page shows our computer **Idle** again.

</Step>
</Steps>

## What we built

We created a workspace and set up our own computer to run its agents. We gave
a task to Triage. Spotlight sent the work to our computer, which started a
fresh container, and Claude Code worked on the task inside it using our
Anthropic key. The agent asked us a question through the inbox, took our
answer, and we closed the task by moving it to Completed.

From here:

- [Make the factory yours](/docs/getting-started/make-the-factory-yours) puts
  the team's lines, which together make up its software factory, in a
  repository as code, points Delivery at our code and changes how Triage works.
- [Lines, stations and tasks](/docs/getting-started/lines-stations-and-tasks)
  explains how a task moves from station to station, and who decides where it
  goes next.
- [Install a host](/docs/hosts/run-a-host) covers running agents on a server,
  and with coding tools other than Claude Code.
