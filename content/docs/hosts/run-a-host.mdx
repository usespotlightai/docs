A host claims work from one pull pool and starts the sandboxes its runs work
in. Before you install one, have ready:

- The pool's token. If you don't have one, [create a pull pool](/docs/hosts/create-a-pull-pool)
  first.
- Docker, Podman, OrbStack or Colima, running.
- `curl` or `wget`, and `sha256sum` or `shasum`, for the install script.
- `git`, which the host uses to keep mirrors of the repositories runs check out.
- An API key for the harness your lines use, such as an Anthropic key for
  Claude Code.
- A runner image that holds that harness. Spotlight's runner image holds no
  harness. You can build your own after you install the host.

## Install the host

Run the install script with the pool's token, as the command on the Runners
page does. On a [self-hosted Spotlight](/docs/reference/glossary#spotlight-address), use your deployment's address in place of `app.usespotlight.ai`.

```bash
curl -fsSL https://app.usespotlight.ai/api/install.sh | sh -s -- --token <pool token>
```

The script installs the `spotlight` binary, then runs
[`spotlight host init`](/docs/reference/cli/spotlight-command#spotlight-host-init).
It asks how many sandboxes run at once (`5` if you press Enter) and which runner
image to use. To give the answers in the command, as in a script, add flags:

```bash
curl -fsSL https://app.usespotlight.ai/api/install.sh | sh -s -- --token <pool token> --capacity 8 --yes
```

On Linux, run it as root to install a system service with its settings in
`/etc/spotlight`, or as yourself to install a service for your user, with its
settings in `~/.spotlight`. On a Mac, run it as yourself: the host runs as a
launchd agent for your user, beside Docker Desktop, OrbStack or Colima.

When the service runs, this line shows:

```text
The host serves https://app.usespotlight.ai. It shows on the Runners page when it connects.
```

If you did not choose an image, the host uses Spotlight's runner image,
`ghcr.io/usespotlightai/spotlight-runner:<release>`. Below the last line,
`init` prints that this image holds no harness. The host runs change-stack
checks, but no agent run, until it serves an image that holds a harness.

If you install as yourself on Linux and the machine should keep serving after
you log out, run the command `init` prints:

```bash
loginctl enable-linger $USER
```

If you want to run the host under your own supervisor instead of a service,
add `--no-service` to the install command, then start the host with
`spotlight host`.

## Give the host a harness

Build an image `FROM` Spotlight's runner image, with the harness your lines
use, and make it the host's image with `spotlight host config set image=<image>`.
[Install a harness in your runner image](/docs/hosts/install-a-harness-in-your-runner-image)
gives the steps.

## Give the host your harness key

Write the key to `sandbox.env`, beside the host's configuration.

<Tabs items={['As root', 'As yourself']}>
<Tab value="As root">

```bash
echo 'ANTHROPIC_API_KEY=<your key>' | sudo tee -a /etc/spotlight/sandbox.env
sudo chmod 600 /etc/spotlight/sandbox.env
```

</Tab>
<Tab value="As yourself">

```bash
echo 'ANTHROPIC_API_KEY=<your key>' >> ~/.spotlight/sandbox.env
chmod 600 ~/.spotlight/sandbox.env
```

</Tab>
</Tabs>

The sandbox never sees `host.env`, so keys go in `sandbox.env` only. For
Codex, Cursor, OpenCode or a Claude subscription, see
[Give hosts your harness keys](/docs/hosts/give-sandboxes-your-harness-keys).

Then have the host read the new key:

```bash
spotlight host reload
```

## Change the host settings

Change a setting with `spotlight host config set`, as in:

```bash
spotlight host config set capacity=8
```

The command checks the new value before it saves it. Most settings, such as
`capacity` and `image`, apply to the running host at once. Running sandboxes
keep going. A few, such as `token` and `url`, need a restart: the host restarts
when its running sandboxes finish. Spotlight drains each of them as soon as no
run is in it, so a sandbox waiting for a task's next run stores its workspace
and stops. To restart at once and stop them, add
`--now`. `spotlight host config keys` lists every setting and when it applies.

For a host installed as root, run each `spotlight host` command with `sudo`.

To see the settings, run `spotlight host config`. To remove one so its default
applies, run `spotlight host config unset <key>`.

## Check that it is serving

Open **Settings** from the workspace menu, then **Runners**. The machine
appears in its own row
with its name, the pool it came through under **Serves**, and the harnesses its
runner images hold under **Harnesses**. Its status reads **Idle** until it claims a run.

If **Harnesses** reads **None** in red, the host's images hold no harness. See
[Check that it is served](/docs/hosts/install-a-harness-in-your-runner-image#check-that-it-is-served).

If the machine does not appear within a minute, check the host:

```bash
spotlight host status
```

It shows whether the service runs, how many sandboxes run, and the settings.
Its checks say whether Spotlight accepts the token and whether the container
runtime answers, each with what to do if not. To read the host's log, run
`spotlight host logs`, or `spotlight host logs -f` to follow it.

The host exits with code `3` when Spotlight does not accept its token. Check that the
token belongs to a pool that still exists and has not been rotated.

## Remove the host

```bash
spotlight host uninstall
```

The command stops and removes the service, then asks whether to delete the
settings and the host's state too. `--purge` deletes them without the question.
