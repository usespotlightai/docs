A task assigned to you stops at its station and waits for you when the station
asks you something, when its run fails, when a tool needs your approval, or
when a tool needs to act as you at a service you have not connected.
Each of these is an item in your inbox. Items that grade a run, propose
memories or report a station alert are inbox requests. They wait on nothing,
and so do notices about your team's work that need a person, such as a config
pull request that Spotlight opened.

## Open the item

Open **Inbox** in the workspace sidebar and select an item under **Open**.
**Running** and **Resolved** are at the bottom of the list and are collapsed
at first. Items under **Resolved** are read-only. The right pane shows the conversation:
what the station was asked to do, the steps it took, and what it said last. The row's
preview line and the last note tell you what it is waiting on.

If the row shows `×N`, the same failure has happened N times. Before you
answer again, follow
[Troubleshoot a run](/docs/runs/troubleshoot-a-run).

## Answer the station

Write your reply in the box at the bottom of the item that reads **Reply…**.

- Press Enter to send. Press Shift+Enter for a new line.
- To give the station files, select **+**, or drop or paste them on the box.

The run that asked carries on in the same conversation and reads your answer
as the next message to it. If that run failed or was stopped, a new run
starts at the same station and picks up the conversation. While that run
works, the item is under **Running**. Select it there to follow the steps of the
run live in the same pane. When the station asks you something again, the item
goes back under **Open**.

If the task was opened from Slack, a reply in the thread where its question was
posted answers the item too. See
[Open tasks from Slack and post questions back](/docs/integrations/open-tasks-from-slack).

## Follow your running work

**Running** shows the work that does not wait on you: every run that is queued
or in progress on a task assigned to you, at any station. Select a run to
follow its steps in the right pane. When the run asks you something, its item
goes under **Open**.

## Approve, edit or dismiss a request

An approval item says what the agent would like to do, in its own words, above
a card titled **Waiting for your approval**. The card shows the call itself:
the inputs of a tool call, or the command of a harness permission. It comes
from a tool that requires approval or from a harness permission a profile sets
to ask.

- To let the call run as it is, select **Approve**.
- To change it first, select the pencil icon, change the values in place, and
  select **Approve**. Every input that had a value needs one. Only a tool call
  can be edited; a harness permission is approved or dismissed as it is.
- To run it yourself instead, select the copy icon.
- To dismiss it, select **Dismiss**. If the agent should know why, write it in
  the field that opens, then select **Dismiss** again.

The card's title then reads **Request approved**, **Request approved with
changes** or **Request dismissed**, and the run that asked carries on in the
same conversation. If the runner did not keep the run's workspace, that run
has completed, and your answer starts a new run at the station, which picks up
the station's conversation. If you
changed the call, the agent is told what you changed, and the tool runs with
your values. An approval covers one call; the next call asks again. A
dismissal stays valid: the same call with the same inputs at this station is
dismissed without asking you.

If Spotlight cannot take your answer, the card says why. See
[Answering an approval](/docs/reference/errors-and-messages#answering-an-approval).

If you write a reply instead of choosing, the run carries on with no decision
and you are asked again when the agent next makes the call.

## Connect a service a tool acts as you in

On a task you started, a tool may act as you at a service, and wait until you
connect your account there. The item says which tool needs it, and nothing has
been sent yet. Select **Connect**, sign in and approve at the service, and you
come back to the item. It is answered with `Connected <Name>.` and the work
resumes. The connection stays for later tasks; see
[Connect yourself](/docs/integrations/connect-an-integration#connect-yourself).

## Grade a judged run

An item that reads **A judged run needs your grade. Grades check the judge.**
asks for your view of one run at a station with a judge. It shows the run's
conversation, then a card with the question and, where the station has one,
the judge's rubric. Select **Yes** or **No**, or a number from 1 to 5. Your
grade saves as soon as you choose. Anyone on the team, or an owner or admin of
the workspace, can grade it, and nothing waits on it. See
[Check a station's judge against people](/docs/improvement/check-a-stations-judge-against-people).

## Look into a station alert

An item that reads **Station alert fired.** names the
alert that fired and charts its measure run by run. Only people
on the team and the workspace's owners and admins get it. Nothing waits on it.

- To compare the station with the rest of the team, select **Open in
  Insights**.
- To ask the agent for a change to the station, select **Improve**. The Agent
  page opens a new chat with the station attached. Go on as in
  [Ask the agent for a change](/docs/improvement/improve-a-station-from-its-runs#ask-the-agent-for-a-change).

The item resolves itself once the alert resolves, which takes as many runs as
the alert compares. It opens again if the alert fires again soon after. See
[Station alerts](/docs/reference/app/tasks-runs-and-the-inbox#station-alerts).

## Review the memories a run proposed

When a station drafts memories from a run, or the agent proposes one with
`spotlight remember`, the item shows the run's conversation, then a line such
as `Claude Code proposed 2 memories · 2 to review`. Each memory has its own
card titled `Waiting for your approval`, with the memory, its kind, where it
applies, any repository and paths it is about under **Files**, and, under **Source**,
what it was drawn from. See
[Memory reviews](/docs/reference/app/tasks-runs-and-the-inbox#memory-reviews).

- To keep it, select **Approve**.
- To change it first, select the pencil icon, change the text in place, and
  select **Approve**.
- To drop it, select **Reject**.

The card's title then reads `Memory approved by <name>` or
`Memory rejected by <name>`, with the name of the person who decided.

## Act on a notice

A notice has a lightbulb beside its headline. Most notices go to every member
of your team. When one of you opens it, it is resolved for the whole team: it
moves under **Resolved** and leaves the inbox 30 days later. A notice about a
change that you asked to test in a chat, and that did not become the pull
request, goes to you alone. Read the points under
**Details**, and select **Open the station** under them to open the station.

- If Spotlight opened a config pull request, select **Review the pull
  request** to open it on GitHub. Its description says what changes, how the
  candidate scored and why, task by task. Merge it to change the station, or
  close it to say no to its config.
- If Spotlight could not open the pull request, the points give the reason,
  such as a line with no `source` block. Fix it in the line's Terraform.
- If Spotlight cannot search a station, the points say what to fix, such as
  `Please add a judge or a check to the station in the Terraform of the line.`
- If a search stalled on causes outside the config, each point names a task,
  its cause and what to fix, such as the judge's rubric or the station's
  check.
- If a change that you asked to test did not become the pull request, the
  first point says why, such as `No candidate did better than the live config
  on the held-out tasks.` or `Candidate <name> became the config pull
  request.`, and the next ones how each of your changes did. If another
  candidate became the pull request, the team gets that notice. To try another change, go back to the chat. See
  [Test the change](/docs/improvement/improve-a-station-from-its-runs#test-the-change).

See [What a person does](/docs/improvement/how-spotlight-improves-a-station#what-a-person-does)
and [Notices](/docs/reference/app/searches#notices).

A search that you did not ask for and that ends with no pull request sends no
notice, nor does a config
pull request that merges, or that Spotlight closes because the station's live
config changed. See
[What happens to the pull request](/docs/improvement/how-spotlight-improves-a-station#what-happens-to-the-pull-request).

## Send the task somewhere else instead

If another station should take the work, say so in your answer, and the agent
passes the task on. To stop work on the task or close it, move it to
**Backlog** or **Completed**, as in
[Add a task and move it along a line](/docs/tasks/add-and-move-tasks#move-the-task).
The item then reads `The task moved on to <Station>. Nothing is left to answer.`
in place of the box, or `The conversation is closed here. Nothing is left to answer.`
if the task is still at the item's station.
