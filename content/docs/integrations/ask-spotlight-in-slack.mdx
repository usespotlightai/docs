title: Ask Spotlight in Slack
description: Add the Slack module so a mention of your Slack app starts a chat with the team's agent, and tasks' questions are posted back to Slack.
---

The agent answers in the mention's thread and can propose tasks, which you
accept or dismiss with a button. You need:

- Permission to create and install apps in your Slack workspace.
- Terraform 1.11 or later, set up with the Spotlight provider, using a token
  that has the `configure` and `secrets` scopes. See
  [Manage Spotlight with Terraform](/docs/configuration/manage-spotlight-with-terraform).
- To connect the app: to be an owner or admin of the Spotlight workspace.
- A Spotlight account for each person who mentions the app, on the team that
  holds the integration. The email of their Slack account is their sign-in
  email or an email they verified. See
  [Add another email to your account](/docs/administration/add-another-email-to-your-account).
- On a self-hosted Spotlight with an [outbound allow-list](/docs/reference/self-hosted-settings#allowed-hosts), the
  list includes `slack.com` and `files.slack.com`. Spotlight calls Slack's API
  and downloads Slack files from its own servers.

## Get the app manifest

The [Slack module](https://registry.terraform.io/modules/usespotlightai/slack/spotlight)
creates the Slack integration on the team, and gives a Slack app manifest
with the addresses, scopes and events the app needs. With `create = false`, it
creates nothing and gives the manifest. A task created from a Slack chat
posts its questions to the channel of that chat, each in a new thread.
`routes` names the channel for questions from a line's other tasks, by the
line's key (`delivery` is the built-in Delivery line's key): replace
`<channel id>` with the ID of that channel.

```hcl
terraform {
  required_providers {
    spotlight = {
      source  = "usespotlightai/spotlight"
      version = "0.1.0-rc.4"
    }
  }
}

module "slack" {
  source  = "usespotlightai/slack/spotlight"
  version = "0.1.0-rc.12"

  create = false

  workspace = "acme"
  team      = "core"

  routes = {
    delivery = "<channel id>"
  }
}

output "slack_manifest" {
  value = module.slack.manifest
}
```

The module and the provider are release candidates, and Terraform selects a
release candidate only for an exact version. Keep both versions exact. If your
configuration already has a `required_providers` block, set the provider's
`version` there.

Change `workspace` to the part after `/w/` in the workspace's address, and
`team` to your team's key. On a [self-hosted Spotlight](/docs/reference/glossary#spotlight-address), set
`spotlight_url` to your deployment's address. Run `terraform apply`, then:

```bash
terraform output -raw slack_manifest
```

## Create the Slack app

<Steps>
<Step>

At [api.slack.com/apps](https://api.slack.com/apps), select **Create New App**,
then **From a manifest**. Choose your Slack workspace and paste the manifest.
If Slack says that it cannot verify the request URL, continue. The address
answers once the integration exists.

</Step>
<Step>

Turn on **Agents & AI Apps** in the app's settings. Slack then shows a status
in the thread while the agent works.

</Step>
<Step>

Under **Basic Information** › **App Credentials**, copy the client ID, the
client secret and the signing secret.

</Step>
</Steps>

If you already have a Slack app, paste the manifest on its **App Manifest**
page instead, and reinstall the app if Slack asks.

## Create the integration

Add the app's credentials to the module, and remove `create = false`:

```hcl
variable "slack_client_id" {
  type = string
}

variable "slack_client_secret" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "slack_signing_secret" {
  type      = string
  sensitive = true
  ephemeral = true
}

module "slack" {
  source  = "usespotlightai/slack/spotlight"
  version = "0.1.0-rc.12"

  workspace = "acme"
  team      = "core"

  client_id      = var.slack_client_id
  client_secret  = var.slack_client_secret
  signing_secret = var.slack_signing_secret

  routes = {
    delivery = "<channel id>"
  }
}
```

The module keeps the client secret and the signing secret as workspace
secrets. The agent reads the repositories of the team's lines. To answer with
another harness, set `harness`, as in `codex`. To show another status while
the agent works, set `status`, or set it to `null` for no status. To react with
other emojis when a task is complete, when a run of it fails, or when a mention
reopens it, set `finished_reaction`, `failed_reaction` and `acknowledge`, or
set them to `null` for no reaction.

Run `terraform apply`. Then open the app's **Event Subscriptions** page in
Slack and select **Retry** next to the request URL. Slack sends a challenge,
Spotlight responds to it, and Slack marks the address verified.

## Connect the app

<Steps>
<Step>

In Spotlight, open **Settings** from the workspace menu, then **Integrations**
under the team's name.

</Step>
<Step>

Select **Connect team account** on the Slack row.

</Step>
<Step>

Allow the app in Slack. Slack installs the app in your Slack workspace.

</Step>
</Steps>

Slack sends you back to **Integrations**. Open the Slack row: **Team account**
shows the name of your Slack workspace. Until the team is connected, the app
answers nothing in Slack. See
[Connect an integration that signs in with OAuth](/docs/integrations/connect-an-integration).

## Choose what the app posts

By default, the app posts the questions of tasks and says in a task's thread
when the task is complete. Set `notify` to choose what it posts:

| Value | What the app posts | Where |
| --- | --- | --- |
| `questions` | The questions of tasks. | The channel of the task's Slack chat, or else the channel in `routes` for the task's line. |
| `finished` | A message that the task is complete. | The task's thread. |
| `inbox_requests` | A request that waits for a person in the inbox: a run to grade, proposed memories, or a station alert. | The channel of the task's Slack chat, or else the channel in `routes` for the task's line. |
| `notices` | A notice of the team that is addressed to nobody, such as a config pull request that Spotlight opened. | The channel in `notices_channel`. |

```hcl
module "slack" {
  # ...

  notify          = ["questions", "finished", "inbox_requests", "notices"]
  notices_channel = "<channel id>"
}
```

Each post has an **Open in Spotlight** button. A notice that links to a pull
request also has a button to it. When a request has no channel,
because its task did not come from Slack and its line has no route, the app
does not post it. A notice that is addressed to one person stays in that
person's inbox. The app posts a request or a notice once, when it first opens.
Without `questions`, nobody can answer a question in Slack.

## Check it

Mention the app in a channel it has joined, with a question about your code.
While the agent works, the thread shows "is thinking…". The agent's answer
then appears in the thread, with an **Open in Spotlight** button. The chat also
shows on your **Agent** page. Files attached to the mention, such as
screenshots, go to the agent with it. To ask more, mention the app again in
the same thread. Only the person who started the chat can talk to it. When another
person mentions the app in that thread, the app replies that only the person
who started the chat can talk to it, and the chat does not change.

Ask for a change. When the agent proposes a task, its answer lists the open
proposals, each with a number that it keeps and an **Accept** and a
**Dismiss** button. Click **Accept** to create the task, or **Dismiss** to
remove the proposal. You can also reply with a mention and `accept` or
`dismiss`, and add the number when more than one proposal is open, as in
`accept 2`. The thread then links to the new task. When the task asks a
question, the question appears in the channel in a new thread and mentions
you. The images of the question, such as screenshots of the change, show
below it. The app waits up to 10 seconds until Slack has processed them, and
posts the question without them when Slack has not. A reply in that thread
answers it and resumes the work. On the task in Spotlight, the reply shows the
avatar of the member who uses the email of your Slack account. A mention of the
app at the start of the reply is removed.

When a run of the task fails, the app reacts to the first message of that
thread with `x`. When the task is complete, the app removes `x`, reacts with
`white_check_mark` and says so in the thread, with the pull request. When the
task asked no question, the reactions go on your first mention instead.

After the task finishes, mention the app in that thread to ask for more. The
mention reopens the task, the app reacts with the `eyes` emoji, removes
`white_check_mark`, and the agent works on the task again. A task at Completed
does not reopen. The app then replies that you must mention it in a new
message.

If the app replies that no member uses your email, check that the email of
your Slack account is your Spotlight sign-in email or a verified email under
**Settings** › **Emails**. If it is neither,
[add it to your account](/docs/administration/add-another-email-to-your-account).
Also check that the app has the `users:read` and `users:read.email` scopes.

If the app replies that the team's lines run in different images, the agent
cannot read all their repositories in one chat. Give the team's lines one
image. See [Repository fields](/docs/reference/terraform/line#repository-fields).
