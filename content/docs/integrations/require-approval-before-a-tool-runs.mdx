title: Require approval before a tool runs
description: Make an integration's tool wait for a person to approve each call before Spotlight sends it.
---

Use this for tools whose effect is hard to undo, such as posting in public. You
need an integration that offers the tool. If you don't have one, see
[Give stations a tool from an HTTP API](/docs/integrations/give-stations-a-tool-from-an-http-api).

## Add an approval to the tool

In the integration's definition, give the tool an `approval` with `because`:
the reason a person reads before they decide.

```hcl
tools = {
  comment = {
    does        = "comment"
    description = "Comment on the issue."
    inputs = {
      issue = { type = "string", required = true }
      body  = { type = "string", required = true }
    }
    approval = {
      because = "It posts publicly, under the team's name."
    }
  }
}
```

The agent says what it would like to do in its own words when it calls the
tool, working from the tool's `description` and `because`. Write both so that
a person reading that sentence knows what the call does and why it waits for
them.

Don't give the tool an input named `intent`. Spotlight keeps that name for the
agent's sentence, and refuses the integration otherwise.

Run `terraform apply`.

## Approve, edit or dismiss each call

When an agent calls the tool, nothing is sent: the task's inbox item shows
what the agent would like to do and the call itself, with **Approve** and
**Dismiss**. A person can change the call's inputs before approving it. The
work resumes once someone decides. See
[Answer the inbox](/docs/inbox/answer-the-inbox#approve-edit-or-dismiss-a-request).

If agents should ask before commands or file changes instead of tool calls,
use a harness profile's `ask` rules. See
[Limit what agents may do](/docs/agents/limit-what-agents-may-do).
