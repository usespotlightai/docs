title: Steer or stop a run
description: Tell an agent something while its run works, or stop the run and take the task back.
---

The members of the task's team, and the owners and admins of the workspace,
can stop a run. They can talk to it too, but a message that puts the task on
hold comes only from a member of the team. Only a person the run waits for can
answer its question, or, while a person holds the task, anybody who acts on
the team. To answer for a task assigned to someone else, assign it to yourself
first with the assignee control under **Properties** on the task page (it reads
**Assign this task** or `Assigned to <name>`).

## Open the run

Open the task and select the run under **Activity**, or open it from **Runs**
in the team sidebar. The Run page shows the agent's steps as they happen, with
a working indicator while the run is queued or working.

If the row says **Queued**, no runner has claimed it yet. If it stays that
way, see [Troubleshoot a run](/docs/runs/troubleshoot-a-run).

## Message the agent

Write in the box at the bottom of the Run page that reads **Write a message…**,
and press Enter. Shift+Enter makes a new line. To add files, select **+**, or
drop or paste them on the box.

The agent gets your message within a few seconds, in the middle of what it is
doing: its current turn is interrupted and your words become the next thing
it reads. Its reply and the steps that follow appear on the same page.

When the run waits for your answer, it reads **Waiting for you** and the box
reads **Answer the question to continue the run…**. What you send answers the
agent's question and the run carries on. The answer is yours when you are the
task's assignee, the question asks you by name, or the task has no assignee
and you are a member of its team. While a person holds the task, everyone who
acts on the team can answer.

While the run waits for someone else's answer, the box is closed and reads
`It waits for another person to answer.`

At a station with an agent, while nobody holds the task, a message to a run
at the task's station that answers no question puts the task on hold, and the
task is assigned to you. This is so for an older run at the station too, and a
run that works there stops. Then the box reads **Your message puts the task on
hold…**. Only members of the team can be assigned, so for an
owner or admin of the workspace who is not on the team, the box is closed and
reads `Your message would put the task on hold, and a hold assigns the task to
you. Only members of the team can do that.`

While a person holds the task, your message tells the agent what to do next,
and the box reads **Tell the agent what to do next…**.

A message does not answer an approval, so the box does not read **Answer the
question to continue the run…** for one. What you send is a message that
answers no question, as above. To decide the approval, select **Approve** or **Dismiss** on its card,
or select **Open in the inbox**.

Once the task has left this station, the box talks to the newest run at the
task's new station, and its label names that station. If no run is there
yet, the box is closed and reads `The task has moved to <Station>. Messages
here reach no one.`

## Send work back to a station

When the task has finished at a station that is not Completed, the box on a
run at that station reads **Say what to change…**.
Say what to change and press Enter. The task is no longer finished. If an
agent works at the station, a new run starts there and picks
up its earlier conversation with your message, and its agent passes the task
on from there. To have an earlier station redo work, tell the current
station's agent where to pass it: Code Review can pass it to Implementation or
Spec.

## Stop the run

While a runner is working the run, and with the composer empty and nothing
attached, the send button becomes a square **Stop** button. Select it. The
Run page does not offer it while the run is **Queued**. When the box is
closed for an owner or admin of the workspace who is not on the team, **Stop**
is still there.

The agent is stopped where it is. An item opens in the inbox of the task's
assignee, or of its team when the task has no assignee, with "A person stopped
the run. The task is back with you." Stopping a run does not assign the task
to you. The task stays at the same station. To carry on there, reply to the item, which
starts a new run at that station; see
[Answer the inbox](/docs/inbox/answer-the-inbox).

The same **Stop** button is in the inbox item's composer while a run works on
it.

## Park or close the task

To stop work on the task, move it to **Backlog**; to close it, move it to
**Completed**, as in [Add a task and move it along a
line](/docs/tasks/add-and-move-tasks#move-the-task). A working run is stopped,
one waiting for an answer is ended, and one still queued is cancelled and shows
as **Cancelled**.
