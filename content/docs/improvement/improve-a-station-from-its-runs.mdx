title: Improve a station from its runs
description: Compare how a station's runs turned out under each config, have the agent propose a change from them and test it on past tasks, and merge the pull request Spotlight opens.
---

Use this when a station's runs keep failing, get sent back or cost more than
they should. You need:

- To be on the team, or an owner or admin of the workspace. Only they can see
  how the station's runs turned out.
- A host serving the workspace with the harness you want to plan with. The
  chat runs there like any other run. See
  [Install a host](/docs/hosts/run-a-host).
- The team's configuration in Terraform, to apply the change. See
  [Manage Spotlight with Terraform](/docs/configuration/manage-spotlight-with-terraform).

## Read how its runs turned out

<Steps>
<Step>

Open the line's board and select the name of a work station. On the Station
page, read **Latest runs on this config** and **Recent runs**.

</Step>
<Step>

To compare configs, select **See in Insights**. Under **Runs by config**,
compare neighbouring groups, expand a group to list its runs, and select a
run's ending to open it.

</Step>
</Steps>

[Station outcomes](/docs/reference/app/tasks-runs-and-the-inbox#station-outcomes)
says what each part shows and how runs are grouped.

## Ask the agent for a change

<Steps>
<Step>

On the Station page, under **What needs attention**,
select **Ask the agent** beside the signal you want to fix. The Agent page
opens a new chat with the station already in the message, the same way a
shared trace appears, and the signal written out before **What should change
at this station?** If no signal is listed, select **Review with agent**
instead. To start an ordinary chat, delete the station from the message.

</Step>
<Step>

In the agent picker in the composer, choose the harness under **Harness**.
For a model other than the harness's default, choose it under **Model**. If
the harness offers an effort, choose it under **Effort** the same way.

</Step>
<Step>

If the team's Terraform is in a GitHub repository the GitHub App can see,
select **No repositories** below the composer and tick it. The agent then writes its proposal against the files
as they are.

</Step>
<Step>

Add to the message what the station should do better, such as the runs you
saw sent back, and press Enter.

</Step>
</Steps>

The first message names the station and its line. The agent writes
the station's recent runs into its workspace with
[`spotlight history`](/docs/reference/cli/agent-commands#spotlight-history) and
reads them. It proposes one change at a time, and says which outcome should
show that the change worked.

## Test the change

The agent tests its change with the
[`test-station-change`](/docs/reference/built-ins/built-in-tools-and-skills#test-station-change)
tool: Spotlight replays the change against the live config on the station's
replay set. The agent says in the chat what happens next.

- To have the search agent refine the change, ask the agent for a search in
  place of a test. If a search of the station is already running, the change
  joins it as one candidate, with no refinement of its own.
- If the change did better, Spotlight opens a config pull request, and your
  team gets an item in the inbox that links to it. Review it, and merge it to
  change the station. Otherwise you get an item that says why the change did
  not hold up. See
  [Answer the inbox](/docs/inbox/answer-the-inbox#act-on-a-notice).
- A station takes at most 3 tests a day. Asking again with the same change
  starts nothing new.
- If the test cannot start, the agent gives the reason, such as an open config
  pull request for the station, and shows the change as a diff of the station's
  block in the line's `spotlight_line` resource and of its prompt file,
  `prompts/<team>/<line>/<station>.md`. Make that change yourself, as below.
  See [Test refusals](/docs/reference/errors-and-messages#test-refusals).

Reply in the chat to question the proposal or ask for another one.

## Apply a change by hand

If the test could not start, apply the agent's diff:

<Steps>
<Step>

Make the proposed change in the team's Terraform: the station's block, its
prompt file, or both. See
[Change a line's stations](/docs/lines/change-a-lines-stations).

</Step>
<Step>

Run `terraform apply`.

</Step>
</Steps>

If the line [checks its pull requests](/docs/configuration/check-terraform-pull-requests-for-station-regressions),
CI replays the change on the station's replay set before it merges.

## Check whether it helped

Once runs at the station have ended with the new config, open the station
again and select **See in Insights**. Their group is at the top of **Runs by
config**, named by the first of its changes. Compare it with the group below
it, or select **Impact** on it to set the runs before the change against the
runs after it.

If the change did not help, say so in the same chat and ask for the next
change.
