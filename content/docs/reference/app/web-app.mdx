The web app is served at `https://app.usespotlight.ai`, or at the
deployment's address on a [self-hosted Spotlight](/docs/reference/glossary#spotlight-address). Every page except `/login` and
`/invites/<token>` is behind sign-in. Routes below are relative to the
Spotlight address; `<slug>` is the workspace's slug and `<teamId>` a team's id.

The web app shows configuration read-only. Lines, stations, skills,
integrations, hooks, harness profiles, secrets, pools and trusts are written
through the [resource API](/docs/reference/api/resource-api) or the
[Terraform provider](/docs/reference/terraform/terraform-provider). There are
two exceptions: the Add a host page creates pull pools, and the Tokens page
issues and revokes workspace tokens.

## Navigation

The sidebar holds, from the top:

| Item | Leads to |
| --- | --- |
| The workspace menu | "Settings"; "Invite and manage members", which opens the Members page, for an owner or admin; the signed-in email, a switch between the person's workspaces, "Create or join a workspace" and "Log out". |
| "Inbox" | The inbox, with the number of unread items. |
| "Your teams" | Each team the person can see. A team opens to "Agent", "Lines" (one entry per line), "Runs", "Insights" and "Memory". |

"Settings" in the workspace menu opens the settings area, which has a sidebar
of its own. A red dot beside "Settings" means no host is answering.

| Item | Leads to |
| --- | --- |
| "Back to app" | The page the person left the app from, or the inbox. |
| "Workspace" | "General"; "Members", shown only to an owner or admin; "Runners", with the number of hosts answering; and "Tokens", shown only to an owner or admin. |
| Each team the person can see | "General", "Integrations" and "Skills". |

## Pages outside a workspace

| Route | Page | Shows and changes |
| --- | --- | --- |
| `/login` | Log in | "Continue with GitHub". |
| `/workspaces/new` | Create workspace | "Workspace Name", "Workspace URL" and "Team Name", then "Create workspace". See [A workspace created in the web app](/docs/reference/terraform/workspace#a-workspace-created-in-the-web-app). |
| `/invites/<token>` | Accept an invite | "&lt;inviter&gt; invited you to &lt;workspace&gt;", with the role and teams the invite gives ("You join as a member, on the &lt;team&gt; team."). Signed out: "Continue with GitHub", which returns to the page. Signed in with the invited address: "Accept invitation", which joins the workspace and opens its inbox. Signed in with another address: "Invitation is for &lt;invited address&gt;, not &lt;signed-in address&gt;. Please sign in as &lt;invited address&gt; to accept." A closed invite reads "Invitation already accepted.", "Invitation withdrawn." or "Invitation expired. Please ask for a new one."; a link that matches no invite reads "Invitation link doesn't work". See [Invites](/docs/reference/roles-and-permissions#invites). |
| `/github/installed` | GitHub App callback | Connects the installation to the workspace. See [Installation callback](/docs/reference/events/github-events#installation-callback). |

## Workspace pages

| Route | Page | Shows | Can change |
| --- | --- | --- | --- |
| `/w/<slug>/inbox` | Inbox | The person's conversations and notices, newest first, under "Open" and "Resolved". | Nothing on the list itself. |
| `/w/<slug>/inbox/notices/<noticeId>` | Notice | A [notice](/docs/reference/app/tasks-runs-and-the-inbox#notices): its headline, its points under "Details", and its link. | Nothing. Opening it settles it. |
| `/w/<slug>/inbox/<itemId>` | Inbox item | The task's conversation: notes, the runs that worked it and their steps. | Answer the conversation, with attachments. "Approve" or "Dismiss" an approval, edit a tool call's inputs before approving it, or copy the call. "Stop" a run still working the task. Grade a judged run (see [Grades](/docs/reference/app/tasks-runs-and-the-inbox#grades)). "Approve" or "Reject" each memory a run proposed, editing its text before approving it. Read a station alert that went off (see [Station alerts](/docs/reference/app/tasks-runs-and-the-inbox#station-alerts)). Connect an integration a tool needs to act as you (see [Requests to connect](/docs/reference/app/tasks-runs-and-the-inbox#requests-to-connect)). |
| `/w/<slug>/settings/runners` | Runners | One row per host serving the workspace and per push pool, under "Name", "Serves", "Status", "Images", "Harnesses", "Release" and "Last activity", filtered by "All", "Running", "Idle" or "Not answering". A host shows the pool or trust it came through, its standing ("Idle", "Running N of M" or "Not answering"), its default image with `+N` for the others and `N refused` for any it refused, the harnesses its images hold, its release, and `Up since` or `Last seen`. A push pool reads "Push pool", "Starting" or "Running N". Beneath each, one row per runner: the run it holds, or "No run yet", its standing ("Starting", "Running" or "Waiting on a person"), its image, its harnesses and when it started. A run of a team the viewer is not on shows a blurred title, with a tooltip saying it is hidden. | An owner or admin opens "Add a host", or "Add the first host" while there is no host. A member reads "Only workspace owners and admins can add hosts." |
| `/w/<slug>/settings/runners/new` | Add a host | Three steps: "Create a pool", "Add the machine to the &lt;key&gt; pool" and "Wait for the host to connect". The last step waits until a host of the new pool connects; the page then opens Runners. | An owner or admin creates a pull pool under "Pool name", which suggests `my-computer-1` or the next free number, and "Create pool". The page then shows the install command with the pool's token in it, once, with "Copy command". |
| `/w/<slug>/settings/members` | Members | Everyone in the workspace under "Members": name, email, teams ("No team" for none) and role. Under "Pending invites", each open invite: address, teams, "Invited by" and "Expires in N days" or "Expires within a day", and the role it gives. "Filter members" narrows the page with "Show": "Everyone", "Owners", "Admins", "Members" or "Pending invites". Shown to owners and admins only; a member who opens the route is sent to the workspace's own route. | "Invite people" opens the invite dialog: "Email addresses" (separated by commas or new lines), "Invite as" ("Admin" or "Member", the default) and "Teams", then "Send invites". "Invites sent" then lists each address with "Invited", "Sent again", "Already a member" or "Not sent &mdash; please try again". In a member's actions menu, "Change role". In an invite's actions menu, "Resend invite" and "Revoke invite". |
| `/w/<slug>/settings/tokens` | Tokens | Each [workspace token](/docs/reference/api/workspace-token) a person issued: its name, when it was created, "No expiry", "Expires" with the date, or "Expired", and its scopes. Never the token itself. A member who opens the route is sent to the workspace's own route. | An owner or admin can "Create a token" with "Name", "What it is for", "What it may do" and "Expires after". "What it may do" is one of "Read", "Plan" or "Configure" (the default), with "Secrets", "Runners" and "Token trusts" beside it; "Expires after" is "30 days", "90 days" (the default), "1 year" or "Never". The page then shows the token, once, with "Copy token"; "I've copied it" dismisses it. "Revoke token" in a token's actions menu, then "Revoke token" again, revokes one. |

See [The inbox](/docs/reference/app/tasks-runs-and-the-inbox#the-inbox) for what
an inbox item holds and who may answer it.

## Team pages

All team routes start with `/w/<slug>/team/<teamId>`, except a team's
settings pages, which start with `/w/<slug>/settings/team/<teamId>`. The
team's own route opens its first line, or "Runs" when it has none.

| Route | Page | Shows | Can change |
| --- | --- | --- | --- |
| `…/agent` | Agent | The person's chats with the team's agent. | Start a chat under "Plan with the agent", with traces or a station to improve attached. |
| `…/agent/<chatId>` | Chat | The chat's messages and the tasks the agent proposed. | Say something, with attachments and shared traces. "Create task" or "Dismiss" a proposal. |
| `…/lines/<lineId>` | Board | The line's stations as sections, with the tasks standing at each. The views "Backlog" (the backlog station), "Active" (work stations, the default) and "Completed" (the completed station). A task shows "Awaiting review" or that it is in progress. | Create a task under "New task" (title, description, attachments, "Create more", "Create task"). Reorder tasks within a station by dragging. Start selected backlog tasks, or park selected tasks, with "Move to". |
| `…/lines/<lineId>/stations/<stationId>` | Station | The station's name and description. A backlog or completed station shows only that nothing runs there. A work station has the tabs "Overview", the default, and "Improve"; another tab reads "Station not found". "Overview" shows "Latest runs on this config", over the config in force (see [Station outcomes](/docs/reference/app/tasks-runs-and-the-inbox#station-outcomes)). Then "Config": "Agent", with the harness, model and effort, or "No agent" and `Please pick a harness in Terraform.`; "Prompt", or `No prompt.`; "Skills", with their count and names, or "None"; "Judge" (see [Judge and alerts](/docs/reference/app/tasks-runs-and-the-inbox#judge-and-alerts)); "Ships through", with the line and its repositories; `Alert rules · <n>`, when the station has alerts; and "Version". Then "Runs": "Recent runs". "Version" and "Recent runs" read the newest group of runs with a recorded config, whether its runs started or not. | "See in Insights" and the version's "History" open the station on Insights (see [One station](/docs/reference/app/insights#one-station)), and the judge's "How it agrees with people" opens it at `#judge`. "All runs" opens the Insights Runs tab at the station. "View pull request" opens the pull request a picked search candidate opened for that version. |
| `…/lines/<lineId>/stations/<stationId>/improve` | Station: Improve | For a work station: "What stands out", with "Worth improving": the station's signals that got worse over the past 30 days or that trail the rest of the team, as under "Stations worth improving" on [Insights](/docs/reference/app/insights#overview). With none, it reads `Every signal looks healthy over the past 30 days` and `There's always room to improve. Talk it through with the agent.` Then "Try a change", with "Replay sets", at `#replays` (see [Station page](/docs/reference/app/replays#station-page)), and "Searches", at `#searches` (see [Station page](/docs/reference/app/searches#station-page)). | "Ask the agent" beside a signal opens the Agent page with the station attached to a new chat and the message `<signal> <now> (was <before>, all stations <all>). What should change at this station?` written, leaving out a comparison it lacks. With no signal listed, "Review with the agent" opens it with the station attached. "Create a replay set" asks for a name, then opens the new set's page. "Start a search" starts a search over one of the station's sets. |
| `…/lines/<lineId>/stations/<stationId>/replay-sets/<setId>` | Replay set | Under "Replays", the set's replays with their state, success, gain over the baseline and spend; under "Health", its noise, room to improve, judge and checks readings; under "Runs", how its runs turned out, each run and whether it can still be replayed; under "Checks", the checks replayed on it. See [Replay set page](/docs/reference/app/replays#replay-set-page). | "Rename" or "Delete" the set. Turn "Guards config changes" on or off. "Add runs" from the station's latest ended runs, with runs suggested to even the mix, or take one out. "Start a replay" under a candidate or the live config, within a ceiling, replaying each run 1 to 5 times. |
| `…/lines/<lineId>/stations/<stationId>/searches/<searchId>` | Search | A header with `Search <n>`, a pill for some endings, the replay set's name, linked, and when it ended, or started while it has not ended; tiles for the best candidate, the live config, iterations, tasks and spend; a `Why it stalled (iteration <n>)` card for each reflection; the "Candidates" card, each iteration's candidates with their scores, gains, cost and pull request, and a candidate's details beside it; and "Success against cost". See [Search page](/docs/reference/app/searches#search-page). | "Stop" a search under way. "Pick" a candidate to open a pull request. |
| `…/lines/<lineId>/stations/<stationId>/replays/<replayId>` | Replay | A header with the candidate's name, a "Stopped", "Over budget" or "Baseline" pill, the set's name, linked, `from its search` for a search's replay, and when it ended, or started while it has not ended; tiles for the replay's success and what scored it, its gain over the replay it is compared with, its side-by-side wins and what it spent; then "Tasks", each task's result against that replay, regressions first, and a task's runs, reasons, checks and changes beside it. See [Replay page](/docs/reference/app/replays#replay-page). | "Stop" a queued or running replay. |
| `…/tasks/<taskId>` | Task | Title, description, attachments, and "Activity": every run of the task. Under "Properties": the station, the assignee, "Changes", "View traces" and "Pull request". | Start, park or close the task with the station property. Assign it. "Delete task" from "Task options". |
| `…/runs` | Runs | The team's runs, grouped by age, filtered by "All" or "Awaiting Review". | Nothing. |
| `…/runs/<runId>` | Run | The briefing, the run's config and what changed since the station's previous run (see [Config](/docs/reference/app/tasks-runs-and-the-inbox#config)), what an ended run spent in cost and tokens (see [Spend](/docs/reference/app/tasks-runs-and-the-inbox#spend)), the judge's score and people's grades (see [Judge score](/docs/reference/app/tasks-runs-and-the-inbox#judge-score)), the run's steps as they happen, and the files it changed. A replay run shows the run it replays, its replay and its result there instead of a conversation (see [Replay runs](/docs/reference/app/replays#replay-runs)). | Say something to the run, with attachments, or send a finished station's work back to it. "Stop" a run a runner holds. Nothing on a replay run. |
| `…/runs/<runId>/changes` | Change stack | The run's change stack: cohorts, layers, each file's changes and notes, and the decisions on each file. | Comment on files and lines, then "Finish review" with a summary and "Comment", "Approve" or "Request changes". The review posts to the task's pull request, or once the task opens one. Dispute a decision by replying to it. |
| `…/tasks/<taskId>/trace` | Task trace | One task's trace: its runs and their steps on a time scale. | Nothing. |
| `…/memory` | Memory | The team's [memories](/docs/reference/glossary#memory), under "Standing" and "Retired", narrowed by "Kind", "Line", "Station", "Repository" and "Path". Each shows its text, its handle, its kind, where it applies, whether it came from a person, a run or outside the team, who kept it, and how many runs used it. A retired memory shows who retired it and why, or that a newer memory replaced it. Opening a memory shows what it rests on under "Source": each note with who said it, a person's name or "From another tool", and each step with the agent that ran it; then "Open the run it came from" and "Open its task", and the memory it replaced. With `?memory=<memoryId>`, the page shows only that memory, with "Show every memory". | "Write a memory": its text, "Kind", "Line", "Station", "Repository" and paths, then "Keep it". On a standing memory, "Edit" opens "Correct this memory", and "Replace it" keeps the correction in place of the memory. "Retire" asks why it no longer holds; runs stop being told it. |
| `…/insights` | Insights | How the team's runs, tasks and pull requests went over a period, against the period before, under "Overview", "Cost", "People", "Productivity", "Stations", "Tools and skills" and "Runs", and the team's task traces under "Traces" (`?tab=traces`). One station's figures, failures, runs by config and judge agreement at `?tab=stations&stationId=<stationId>`. See [Insights](/docs/reference/app/insights). | The period. "Chart" or "Table" on a card that has both. On "Traces", select traces and "Discuss with the agent". "Improve" on a station worth improving opens the Agent page with the station attached. "Impact" on a config change, a diamond or a group of runs by config opens a side panel. |
| `…/settings/general` | General | "Team name", and "Members" with their roles. | An owner or admin can "Add a member": choose someone under "In the workspace" who is not on the team, or "Invite someone new", which opens the invite dialog with the team ticked. Change a member's role. |
| `…/settings/integrations` | Integrations | "GitHub", and each integration the team defines. One the team holds shows "Team account"; one whose `connection.holder` is `requester` shows "Your account", with "Not connected" or "Connected", a rule per tool, and under "People" who has connected. Never a token. | "Install on GitHub" or "Manage on GitHub". An owner or admin can "Connect team account". Anyone can "Connect your account", "Change account" or "Disconnect" it, and set each tool's calls made with their connection to "Allow", "Ask me first" or "Block". See [Connect an integration that signs in with OAuth](/docs/integrations/connect-an-integration#connect-yourself) and [Let a person ask first or block a tool](/docs/integrations/require-approval-before-a-tool-runs#let-a-person-ask-first-or-block-a-tool). |
| `…/settings/skills` | Skills | The team's skills. | Nothing. |

Only the task's assignee may answer, say something to a run or stop it. See
[Roles and permissions](/docs/reference/roles-and-permissions) for who may
invite, change roles and connect GitHub, and
[Change stacks and decisions](/docs/reference/app/change-stacks-and-decisions) for
what a change stack holds.

## Changed only through the resource API

| What | Where it is written |
| --- | --- |
| Workspace name, team name, teams after the first | [`spotlight_workspace`](/docs/reference/terraform/workspace), [`spotlight_team`](/docs/reference/terraform/team) |
| Lines, stations, prompts, reactions, review policy | [`spotlight_line`](/docs/reference/terraform/line) |
| Skills | [`spotlight_skill`](/docs/reference/terraform/skill) |
| Harness profiles | [`spotlight_harness_profile`](/docs/reference/terraform/harness-profile) |
| Integrations and hooks | [`spotlight_integration`](/docs/reference/terraform/integration), [`spotlight_hook`](/docs/reference/terraform/hook) |
| Secrets | [`spotlight_secret`](/docs/reference/terraform/secret) |
| Runner pools, runner trusts, workspace runners | [`spotlight_runner_pool`](/docs/reference/terraform/runner-pool), [`spotlight_runner_trust`](/docs/reference/terraform/runner-trust), [`spotlight_workspace_runners`](/docs/reference/terraform/workspace-runners) |
| Workspace tokens and workspace token trusts | [Workspace tokens](/docs/reference/api/workspace-token), [`spotlight_workspace_token_trust`](/docs/reference/terraform/workspace-token-trust) |
