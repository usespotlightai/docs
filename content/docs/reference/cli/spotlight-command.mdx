`spotlight` is one binary. A host runs `spotlight host`. Each sandbox runs
`spotlight runner` and `spotlight egress` from the runner image. A shared
egress for push pools runs `spotlight egress serve`. An agent runs
the [agent commands](/docs/reference/cli/agent-commands) inside its sandbox.
A person or a CI job runs [`spotlight replay`](/docs/reference/cli/replay-command)
from anywhere to replay a station's past tasks, or to check the station
changes in a Terraform plan. A person runs [`spotlight login`](#spotlight-login)
so that `spotlight replay` and the Terraform provider act as them.
[`spotlight token`](#spotlight-token) prints a token for Terraform's `http`
backend.

## Synopsis

```text
spotlight host
spotlight host init
spotlight host config
spotlight host status
spotlight host reload
spotlight host start
spotlight host stop
spotlight host restart
spotlight host logs
spotlight host uninstall
spotlight host update [release]
spotlight runner
spotlight runner harnesses <json>
spotlight egress
spotlight egress serve
spotlight replay <subcommand>
spotlight login [--url <address>] [--no-browser]
spotlight logout [--url <address>]
spotlight token [--url <address>]
spotlight version
spotlight help [--all] [<command>...]
```

The [agent commands](/docs/reference/cli/agent-commands) work inside a run.

## Help

| Invocation | Output | Exit code |
| --- | --- | --- |
| `spotlight`, `spotlight help`, `-h` or `--help` | The commands, by group, on standard output. Inside a run, the agent commands. Outside one, the commands for hosts, replays and the login. | `0` |
| `spotlight help --all` | Every command, by group. | `0` |
| `spotlight <command> --help`, `-h`, or `spotlight help <command>` | The command's usage, flags, environment, examples, exit codes and docs link. | `0` |
| `spotlight replay` | The help for `spotlight replay`. | `0` |
| `spotlight version` or `--version` | The release, such as `v0.1.0`. A binary built without one prints `dev`. | `0` |

A word that is not a command fails with `spotlight: no command "<word>".` on
standard error and exits `1`. A near command follows, as
`Did you mean spotlight host config?`, then the help to run.

A usage error prints the command's usage line, then
`Run spotlight <command> --help for flags and examples.`

## spotlight host

```text
spotlight host
```

Serves a pull pool or a runner trust. The host claims work, starts a fresh
sandbox and egress for each run or check, and destroys both when it ends.
An unknown subcommand fails as described in [Help](#help).

The host writes its process id to `host.lock` in the state directory while it
holds the lock. The other `spotlight host` commands find it there.

| Signal | Action |
| --- | --- |
| `SIGHUP` | Reloads the settings. See [spotlight host reload](#spotlight-host-reload). Settings with a problem are logged as `could not reload the settings, so the host keeps the ones it has`. |
| `SIGUSR1` | Stops claiming, lets the running sandboxes finish, then starts again in the same process. |
| `SIGINT`, `SIGTERM` | Stops the running sandboxes and exits `0`. |

| Reads | Reference |
| --- | --- |
| The host configuration file and environment | [Host settings](/docs/reference/hosts/host-configuration) |
| The container engine | [Host settings](/docs/reference/hosts/host-configuration#sandboxes) |
| The state directory | [Host settings](/docs/reference/hosts/host-configuration#state) |

The host logs JSON lines to standard output. Each line a sandbox prints
appears in the host's log as an entry with the message `sandbox` and the line
in `line`. Errors that stop the host print to
standard error as `spotlight host: <error>`. When the settings have a problem,
such as no URL or no credential on a machine that is not set up, the error
ends with `To set up this machine as a host, run: spotlight host init`.

| Message | When |
| --- | --- |
| `serving` | The host started. |
| `the container runtime is not answering yet` | The engine did not respond. The host retries. |
| `could not report to the control plane, still trying` | Spotlight did not respond. The host retries. |
| `destroyed a sandbox left behind` | A sandbox from an earlier host process was removed at start. |
| `started a sandbox` | A run or check began. |
| `the sandbox finished` | The sandbox exited. |
| `the sandbox ran past its time` | `SPOTLIGHT_RUN_TIMEOUT` passed. The sandbox is stopped with a 30-second grace, and the run is reported `timed-out`: `Its sandbox ran past the host's limit of <timeout> and was stopped.` |
| `could not start a sandbox; claiming from this image pauses` | Claims for that image pause, longer after each failure in a row, up to about 30 seconds. |
| `failed the work: its egress sidecar did not start` | Egress did not start. The run fails, or the check is skipped. |
| `the host is stopping, so the work is left to be claimed again` | The host stopped before the sandbox started. |
| `the control plane will not have this host; it stops claiming and lets its sandboxes finish` | Spotlight did not accept the host. It exits `3`. |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Stopped on `SIGINT` or `SIGTERM`. |
| `1` | A configuration or runtime error. |
| `3` | Spotlight did not accept the host: an unknown or rotated credential, a host id that is in use by another pool or trust (`409` `host-in-use`), or a host that sent no heartbeat through that pool or trust. |

## spotlight host init

```text
spotlight host init [--url URL] [--token TOKEN | --trust ID --oidc-token-file PATH]
                    [--capacity N] [--image IMAGE] [--name NAME] [--no-service] [--yes]
```

Writes the [host settings](/docs/reference/hosts/host-configuration), pulls the
default runner image and runs the host as a service. Running it again keeps the
saved values as the defaults.

| Flag | Setting | Without the flag |
| --- | --- | --- |
| `--url` | `url` | Asks `Spotlight URL`. Default: the saved value, else `https://app.usespotlight.ai`. |
| `--token` | `token` | Asks `Pool token`, without showing what you type. Enter keeps a saved token. Not asked when a trust is given or saved. |
| `--trust`, `--oidc-token-file` | `trust`, `oidc-token-file` | The saved values. Either flag removes a saved `token`, and `--token` removes a saved trust. |
| `--capacity` | `capacity` | Asks `Sandboxes at once`. Default: the saved value, else `5`. |
| `--image` | `image` | Asks `Runner image`. Default: the saved value, else `ghcr.io/usespotlightai/spotlight-runner:<release>`. That default is not saved, so the host follows its own release. |
| `--name` | `name` | The saved value. Not asked. |
| `--no-service` | | Saves and pulls, but installs no service. Prints `Start the host with: spotlight host`. |
| `--yes` | | Asks nothing. |

`init` asks its questions on the terminal (`/dev/tty`), so they work when the
command reads its standard input from a pipe. With no terminal, or with
`--yes`, it uses the saved value or the default, and stops when it has no token
and no trust.

| Step | Action |
| --- | --- |
| 1 | Checks that a container runtime answers, at the saved `DOCKER_HOST`, else at the usual sockets of Docker, Podman, OrbStack and Colima. Without one it stops before it asks anything, and nothing is saved. |
| 2 | Settles each value from its flag, the answer, the saved value or the default. |
| 3 | Checks the settings as the host does. On a problem it saves nothing. |
| 4 | Asks Spotlight for the host's requirements with the credential. A refused credential stops it, and nothing is saved. When Spotlight does not answer, it warns and goes on. |
| 5 | Saves the settings file in one rename, with mode `0600`. Comments and settings it does not set stay. |
| 6 | Pulls the default image with the [registry credentials](/docs/reference/hosts/host-configuration#registry-credentials). An image with `*` is not pulled. When the pull fails and the machine has a copy, it warns and goes on. |
| 7 | When a host already runs from these settings, restarts it when its sandboxes finish. Otherwise, without `--no-service`, installs and starts the [service](#service-files). |
| 8 | When the default image is Spotlight's runner image, prints that it holds no harness. |

| Message | When |
| --- | --- |
| `Spotlight at <url> accepts the credential` | Step 4. |
| `Spotlight at <url> does not answer, so the credential is not checked: <error>` | Step 4, a warning. |
| `Saved the settings in <config path>` | Step 5. |
| `Pulled <image>` | Step 6. |
| `Could not pull <image>, so the host uses the copy on this machine: <error>` | Step 6, a warning. |
| `Started the systemd service spotlight-host (<unit path>)` | Step 7 on Linux. |
| `Started the launchd agent ai.usespotlight.host (logs in <log path>)` | Step 7 on macOS. |
| `The host serves <url>. It shows on the Runners page when it connects.` | Step 7, when the service started. |
| `The runner image holds no harness, so this host runs checks but no agent run.` | Step 8. Three lines follow with the example images and `Then: spotlight host config set image=IMAGE`. |

As a user other than root on Linux, when lingering is off, it also prints:

```text
To keep the host running after you log out, run:
  loginctl enable-linger <user>
```

| Error | Cause |
| --- | --- |
| `nothing saved, because no container runtime answers. A host runs each sandbox in a container: start Docker or Podman (on macOS, Docker Desktop, OrbStack or Colima), then run this again: <error>` | Step 1. |
| `nothing saved, because <problems>` | Step 3. The problems name the settings by key. |
| `nothing saved, because Spotlight at <url> does not accept the credential` | Step 4. |
| `--token is required: a pull pool's token, from Settings → Runners → Add a host` | No token, no trust and no terminal to ask on. |
| `a pool token is required` | Three empty answers to `Pool token`. |
| `pull <image>: <error>` | Step 6, and the machine has no copy. |
| ``installing a service on <os> is not supported; run `spotlight host` under your own supervisor`` | Step 7 on a platform other than Linux or macOS. |

## spotlight host config

```text
spotlight host config [--json]
spotlight host config get KEY
spotlight host config set KEY=VALUE… [--now]
spotlight host config unset KEY… [--now]
spotlight host config keys
```

Reads and changes the [host settings](/docs/reference/hosts/host-configuration)
file. A `KEY` is a setting's key, such as `capacity`, or its variable, such as
`SPOTLIGHT_CAPACITY`. Any other name in capitals, such as `HTTPS_PROXY`, is
taken as a variable that applies at a restart.

| Subcommand | Action |
| --- | --- |
| `config`, `config list` | Prints the path and each setting the file sets, by key. The token shows as `••••` and its last four characters. |
| `config --json` | Prints `{"path": …, "settings": [{"key": …, "variable": …, "value": …}]}`, the token masked. |
| `config get KEY` | Prints the value the file sets, the token in full. Exits `1` when the file does not set it. |
| `config set KEY=VALUE…` | Sets each value, trimmed. A value is one line. |
| `config unset KEY…` | Removes each setting, so its default applies. |
| `config keys` | Prints each key, its variable, and whether it applies live or at a restart. |

`set` and `unset` check the whole file as the host does, and save nothing when
a check fails:

```text
spotlight host: nothing changed, because capacity: "0" is not a count of at least 1
```

They save the file in one rename, with mode `0600`, and keep its comments and
order. When the environment sets a variable they change, they print
`The environment sets <variable>, which wins over the file.` Then they apply
the change:

| Host | Changed settings | Action | Message |
| --- | --- | --- | --- |
| none runs, service installed | any | none | `The host is stopped. The change applies when it starts: spotlight host start` |
| none runs, no service | any | none | `No host runs from these settings. The change applies when it starts.` |
| runs | all live | [reload](#spotlight-host-reload) | `The running host applied the change` |
| runs | any applies at a restart | [restart](#spotlight-host-start-stop-and-restart) when the running sandboxes finish | `The host restarts with the change when its <n> running sandboxes finish. …` |
| runs | any, with `--now` | restart at once, stopping the running sandboxes | `Restarted the host` |

## spotlight host status

```text
spotlight host status [--json]
```

Prints the settings path, the service, the sandboxes that run against the
capacity, the settings as `config` lists them, and these checks:

| Check | Fails when |
| --- | --- |
| The settings are valid | A setting does not pass the host's checks. |
| The host runs | No process holds the state directory's lock. |
| Spotlight accepts the credential | Spotlight refuses the credential or does not answer. |
| The container runtime answers | No engine answers. |
| The default image holds a harness | A warning only, when the default image is Spotlight's runner image. |

Each failed check prints a line saying what to do. The sandboxes are the runs
whose containers run with the label `ai.usespotlight.host=<host id>`.

With `--json` it prints:

```json
{
  "config": "<config path>",
  "service": { "installed": true, "unit": "<unit path>", "running": true, "process": 4242 },
  "sandboxes": { "running": 2, "capacity": 5 },
  "settings": [{ "key": "capacity", "variable": "SPOTLIGHT_CAPACITY", "value": "5" }],
  "checks": [{ "status": "passed", "message": "The settings are valid." }]
}
```

A check's `status` is `passed`, `warning` or `failed`, and a failed check has a
`fix`. `sandboxes.running` is `null` when no container runtime answers.

| Code | Meaning |
| --- | --- |
| `0` | No check failed. |
| `1` | A check failed. |

## spotlight host reload

```text
spotlight host reload
```

Sends `SIGHUP` to the running host. The host reads its settings,
`sandbox.env` and `egress.env` again, and applies the live settings to the
sandboxes it starts from then on. Running sandboxes keep going. A lower
capacity lets them finish. Settings that apply at a restart wait for the next
one.

| Message | When |
| --- | --- |
| `The running host reloaded its settings, sandbox.env and egress.env` | The signal was sent. |
| `nothing reloaded, because <problems>` | A setting does not pass the checks. Nothing is sent. |
| `no host runs from <config path>` | No process holds the state directory's lock. |

## spotlight host start, stop and restart

```text
spotlight host start
spotlight host stop
spotlight host restart [--now]
```

| Command | Linux | macOS |
| --- | --- | --- |
| `start` | `systemctl start spotlight-host` | `launchctl bootstrap`, or `launchctl kickstart` when loaded |
| `stop` | `systemctl stop spotlight-host` | `launchctl bootout` |
| `restart --now` | `systemctl restart spotlight-host` | `launchctl kickstart -k` |

`systemctl` takes `--user` when the command does not run as root. `stop` and
`restart --now` stop the running sandboxes with the host.

`restart` without `--now` sends `SIGUSR1` to the running host. The host stops
claiming, lets its running sandboxes finish, and starts again in the same
process with the settings it reads then. When no host runs, `restart` starts
the service. When the settings do not pass the host's checks, `restart` sends
nothing and fails with `nothing restarted, because the host would not start: <problems>`.

When no service is installed, each command fails with
``the host is not installed as a service; run `spotlight host init` ``.

## spotlight host logs

```text
spotlight host logs [-f] [-n LINES]
```

Prints the service's log: the last `LINES` lines, `100` by default. `-f` or
`--follow` keeps printing new lines.

| Platform | Reads |
| --- | --- |
| Linux | `journalctl --unit spotlight-host`, with `--user` when not root |
| macOS | `~/Library/Logs/spotlight-host.log` |

## spotlight host uninstall

```text
spotlight host uninstall [--purge] [--yes]
```

Stops the service and removes its unit or agent file. Then it asks
`Also delete the settings <config path> and the state <state>?`. `--purge`
deletes them without the question, and `--yes` keeps them without it. The state
directory is deleted only when it holds a `host-id` file. The binary stays; the
command prints its path.

## Service files

`init` writes the service with the binary at its resolved path (symbolic links
followed) and `SPOTLIGHT_HOST_CONFIG` set to the settings path.

### systemd unit

| | As root | As another user |
| --- | --- | --- |
| Unit file | `/etc/systemd/system/spotlight-host.service` | `~/.config/systemd/user/spotlight-host.service` |
| `systemctl` scope | system | `--user` |
| `WantedBy` | `multi-user.target` | `default.target` |

After writing the unit, `init` runs `systemctl daemon-reload`,
`systemctl enable spotlight-host` and `systemctl restart spotlight-host`.

| Setting | Value |
| --- | --- |
| `Description` | `Spotlight host: a fresh runner for every run` |
| `After` | `network-online.target docker.service podman.socket` |
| `Wants` | `network-online.target` |
| `ExecStart` | `"<binary>" host` |
| `Environment` | `"SPOTLIGHT_HOST_CONFIG=<config path>"` |
| `ExecReload` | `/bin/kill -HUP $MAINPID` |
| `Restart` | `always` |
| `RestartSec` | `5` |
| `RestartPreventExitStatus` | `3` |
| `TimeoutStopSec` | `90` |

### launchd agent

| Key | Value |
| --- | --- |
| File | `~/Library/LaunchAgents/ai.usespotlight.host.plist` |
| `Label` | `ai.usespotlight.host` |
| `ProgramArguments` | `<binary>`, `host` |
| `EnvironmentVariables` | `SPOTLIGHT_HOST_CONFIG=<config path>`, `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin` |
| `RunAtLoad` | true |
| `KeepAlive` | true |
| `ThrottleInterval` | `60` |
| `ExitTimeOut` | `90` |
| `StandardOutPath`, `StandardErrorPath` | `~/Library/Logs/spotlight-host.log` |

`init` runs `launchctl bootout gui/<uid>/ai.usespotlight.host`, then
`launchctl bootstrap gui/<uid> <plist path>`. The agent restarts after exit
code `3` as after any other.

## spotlight runner

```text
spotlight runner
```

The runner image's entrypoint. It does the one run or check its sandbox was
started for, then exits. It takes no arguments other than `harnesses`.
Any other argument fails with `usage: spotlight runner [harnesses <json>]`.

| Variable | Default | Description |
| --- | --- | --- |
| `SPOTLIGHT_URL` | required | The Spotlight address. |
| `SPOTLIGHT_ASSIGNMENT_FILE` | none | The file with the work a host assigned to the sandbox. The host sets it. |
| `SPOTLIGHT_RUN_TOKEN` | none | The one-run credential a push pool's provider passes. |
| `SPOTLIGHT_WORKSPACE` | `/workspace` | The workspace directory. |
| `SPOTLIGHT_AGENT_USER` | none | The user the harness runs as. Spotlight's runner image sets `agent`. When set, the runner must run as root. |
| `SPOTLIGHT_GIT_AUTHOR_NAME` | `Spotlight` | `user.name` in each checkout. |
| `SPOTLIGHT_GIT_AUTHOR_EMAIL` | `noreply@usespotlight.ai` | `user.email` in each checkout. |
| `SPOTLIGHT_EGRESS_URL` | none | With `SPOTLIGHT_RUN_TOKEN` only. The URL of the shared egress the runner sends its traffic through: `runner.egress.url` of the [provision call](/docs/reference/events/provision-call#egress). |
| `SPOTLIGHT_EGRESS_PROXY_CREDENTIAL` | none | With `SPOTLIGHT_EGRESS_URL`. The run proxy credential: `runner.egress.credential` of the provision call. |
| `SPOTLIGHT_EGRESS_TRAFFIC` | `all` | With `SPOTLIGHT_EGRESS_URL`. `bound` sends traffic to hosts that are not bound directly, not through egress. The provisioner passes `runner.egress.traffic` here. See [The runner's local proxy](/docs/reference/hosts/egress#the-runners-local-proxy). |

Exactly one of `SPOTLIGHT_ASSIGNMENT_FILE` or `SPOTLIGHT_RUN_TOKEN` must be set.
The runner reads the `SPOTLIGHT_EGRESS_` variables only with
`SPOTLIGHT_RUN_TOKEN`.

### Messages

| Message | Cause |
| --- | --- |
| `SPOTLIGHT_URL is required` | No address. |
| `SPOTLIGHT_RUN_TOKEN and SPOTLIGHT_ASSIGNMENT_FILE are different ways to get work; set one` | Both set. |
| `SPOTLIGHT_ASSIGNMENT_FILE names the file with the work a host assigned to this runner, or SPOTLIGHT_RUN_TOKEN is the one-run credential a push pool provisioned it with` | Neither set. |
| `its assignment has no one-run credential` | The assignment file contains no credential. |
| `could not trust the egress authority, so TLS through egress may fail` | A warning. The egress authority could not be added to the image's bundles. |
| `nothing was reserved for it in time` | With `SPOTLIGHT_RUN_TOKEN`, no work arrived within 5 minutes. The runner exits `0`. |
| `SPOTLIGHT_EGRESS_URL and SPOTLIGHT_EGRESS_PROXY_CREDENTIAL go together; set both or neither` | Only one of the two is set. |
| `SPOTLIGHT_EGRESS_TRAFFIC: "<value>" is not all or bound` | A value that is not `all` or `bound`. |
| `SPOTLIGHT_EGRESS_URL "<value>" is not an address such as https://egress.example.com` | Not an `http` or `https` URL with a host. |
| `could not open the local proxy, so the work fails` | The runner's local proxy did not open. The run fails before the agent starts. See [The runner's local proxy](/docs/reference/hosts/egress#the-runners-local-proxy). |
| `could not check, because the local proxy did not open` | The runner's local proxy did not open. The change stack check fails. |
| `could not trust the authority of the local proxy, so TLS through it can fail` | A warning. The authority of the local proxy could not be added to the image's bundles. |

The runner logs JSON lines to standard output. See
[Inside a sandbox](/docs/reference/hosts/sandbox) for what it does inside the sandbox.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The run or check ended, whatever its outcome, or nothing was reserved in time. |
| `1` | The runner could not start, or Spotlight did not accept it. |

## spotlight runner harnesses

```text
spotlight runner harnesses '<json array>'
```

Looks for the given harnesses in the image and prints one JSON line with the
runner's release and each harness it found, with its models and version. The
host runs it against each image it supports. See
[Harnesses](/docs/reference/hosts/harnesses).

```bash
spotlight runner harnesses '[]'
```

```json
{"release":"v0.1.0","harnesses":[]}
```

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Printed. |
| `1` | The argument is not a JSON array: `spotlight runner: read the harnesses to look for: <error>`. |

## spotlight egress

```text
spotlight egress
```

The egress sidecar a host starts next to each sandbox. It injects the run's
secrets into requests to their hosts. `spotlight egress serve` runs one egress
for the sandboxes of a push pool. An unknown subcommand fails as described in
[Help](#help).

It logs `egress is the sidecar of the sandbox` when it listens. It reads the
config the host gave it from `/run/spotlight/egress.json` and deletes the file. See
[Egress](/docs/reference/hosts/egress).

```text
spotlight egress serve
```

The shared egress: one long-lived process for the runs of the push pools that
name it. It reads its settings from the environment and logs JSON lines to
standard output. See [Shared egress](/docs/reference/hosts/egress#shared-egress)
for its settings and messages.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Stopped on `SIGINT` or `SIGTERM`. |
| `1` | Egress could not start. |

## spotlight login

```text
spotlight login [--url <address>] [--no-browser]
```

Logs a person in to Spotlight through the browser, with the OAuth 2.0 device
authorization grant (RFC 8628), and keeps the login in the
[credentials file](#credentials-file).

| Flag | Description |
| --- | --- |
| `--url` | The [Spotlight address](/docs/reference/glossary#spotlight-address). Without it, `SPOTLIGHT_URL`, else `https://app.usespotlight.ai`. |
| `--no-browser` | Does not open the browser. |

The address must use `https`. Only a local address, `localhost`, `127.0.0.1`,
`::1` or a name that ends in `.localhost` or `.test`, may use `http`. The
address is kept as its scheme and host, and its port when that is not the
default, so `https://app.usespotlight.ai/` and `https://app.usespotlight.ai:443`
are the same address.

| Step | Action |
| --- | --- |
| 1 | Asks Spotlight for a device code, as the client `spotlight-cli`. |
| 2 | Prints the page to open, `<address>/device?user_code=<code>`, and the code as `XXXX-XXXX`. |
| 3 | When standard output is a terminal and `--no-browser` is not given, opens the page with `open` on macOS or `xdg-open` on Linux. |
| 4 | Asks Spotlight for the login every 5 seconds, 5 seconds more after each `slow_down` answer, until the code is approved, denied or expires after 15 minutes. |
| 5 | Reads the person's email from the new session. |
| 6 | Writes the login for the address to the credentials file, and keeps the logins for other addresses. |

The page is the web app's [`/device`](/docs/reference/app/web-app#pages-outside-a-workspace)
page. The login is a session of the person who approves it. It acts as that
person, with their role in each workspace they are a member of, and ends after
7 days without use. Each use renews it.

| Message | When |
| --- | --- |
| `Open this page to log in to <address>:` | Step 2. The page follows on the next line. |
| `Check that the page shows the code <code>.` | Step 2. |
| `Opened the page in your browser.` | Step 3. |
| `Waiting for you to approve the login. Press Ctrl-C to stop.` | Step 4 starts. |
| `Logged in to <address> as <email>.` | Step 6. |

| Error | Cause |
| --- | --- |
| `the code expired before the login was approved. Run spotlight login again` | 15 minutes passed. |
| `the login was denied in the browser` | The person clicked "Deny". |
| `Spotlight refused the login: <error>. <description>` | Another OAuth error. |
| `Spotlight at <address> did not give a device code. It answered <status>` | Step 1 failed. |
| `Spotlight did not accept the new login token. It answered <status>` | Step 5 failed. |
| `"<value>" is not a Spotlight address. Use a URL such as https://app.usespotlight.ai` | The address is not an `http` or `https` URL with a host. |
| `<value> does not use https. Only a local address may use http` | An `http` address that is not local. |
| `HOME is not set. Set SPOTLIGHT_CONFIG_DIR to keep logins` | No place for the credentials file. |
| `stopped. No login was kept` | `Ctrl-C` or `SIGTERM`. |

Each error is printed after `spotlight login: ` on standard error.

| Code | Meaning |
| --- | --- |
| `0` | Logged in. |
| `1` | An error. |
| `130` | Stopped with `Ctrl-C` or `SIGTERM`. |

## spotlight logout

```text
spotlight logout [--url <address>]
```

Ends the session in Spotlight and removes the login for the address from the
credentials file. The address is found as for `spotlight login`.

| Message | When |
| --- | --- |
| `Logged out of <address>.` | The login was removed. |
| `You are not logged in to <address>.` | The file has no login for the address. |
| `Spotlight did not end the session: <error>. The token stays valid until it expires.` | Spotlight did not answer, or answered with an error. The login is still removed. |

Errors are printed after `spotlight logout: ` on standard error. The exit codes
are those of `spotlight login`.

## spotlight token

```text
spotlight token [--url <address>]
```

Prints a token for Spotlight on standard output, followed by a newline, for
[the state backend](/docs/reference/terraform/state-backend) to send as
`TF_HTTP_PASSWORD`. The address is found as for `spotlight login`. It takes the
first of these that is set:

| Source | Prints |
| --- | --- |
| `SPOTLIGHT_API_TOKEN` | The token, as it is. |
| `SPOTLIGHT_OIDC_TRUST` | A token issued through the [OIDC trust](/docs/reference/terraform/oidc-trust), for the OIDC token in `SPOTLIGHT_OIDC_TOKEN`, else the one GitHub Actions issues to the job for the audience in `SPOTLIGHT_OIDC_AUDIENCE`, else `spotlight`. |
| The login for the address in the [credentials file](#credentials-file) | The login's token. |

| Error | Cause |
| --- | --- |
| `no token for <address>. Run spotlight login, or set SPOTLIGHT_API_TOKEN, or SPOTLIGHT_OIDC_TRUST in CI` | None of the sources is set. |
| `SPOTLIGHT_OIDC_TRUST is set, but no OIDC token was found. Set SPOTLIGHT_OIDC_TOKEN, or run in a GitHub Actions job with the permission id-token: write` | A trust without `SPOTLIGHT_OIDC_TOKEN`, outside a GitHub Actions job that may request OIDC tokens. |
| `GitHub Actions did not give an OIDC token; the job needs the permission id-token: write: <error>` | GitHub Actions refused the request. |
| `Spotlight at <address> did not exchange the OIDC token through the OIDC trust <id>: it answered <status>: <body>` | The trust did not accept the job's token. |

Each error is printed after `spotlight token: ` on standard error. The exit
codes are those of `spotlight login`.

## Credentials file

`spotlight login` writes `credentials.json` in the first of these directories
that applies, on every operating system:

| Directory | When |
| --- | --- |
| `$SPOTLIGHT_CONFIG_DIR` | `SPOTLIGHT_CONFIG_DIR` is set. |
| `$XDG_CONFIG_HOME/spotlight` | `XDG_CONFIG_HOME` is set. |
| `~/.config/spotlight` | Otherwise. |

The file has mode `0600`, and its directory is created with mode `0700`. It
holds one entry for each address:

```json
{
  "logins": {
    "https://app.usespotlight.ai": {
      "token": "<token>",
      "user": "you@example.com"
    }
  }
}
```

The file is written in one rename. Other fields in the file are kept.

| Reads the login | When |
| --- | --- |
| [`spotlight replay`](/docs/reference/cli/replay-command#environment) | `SPOTLIGHT_API_TOKEN` is not set. |
| [`spotlight replay check`](/docs/reference/cli/replay-command#environment-for-check) | Neither `SPOTLIGHT_API_TOKEN` nor `SPOTLIGHT_OIDC_TRUST` is set. |
| [The Terraform provider](/docs/reference/terraform/terraform-provider#credentials) | No token and no trust is set. |
| [`spotlight token`](#spotlight-token) | Neither `SPOTLIGHT_API_TOKEN` nor `SPOTLIGHT_OIDC_TRUST` is set. |

Each takes the entry for the address of its `SPOTLIGHT_URL` or `url`.

## spotlight replay

```text
spotlight replay <subcommand>
```

Proposes replay candidates and starts, follows and stops replays, reading
`SPOTLIGHT_URL` and `SPOTLIGHT_API_TOKEN`, else the login for `SPOTLIGHT_URL`. `spotlight replay check` checks a
saved Terraform plan's station changes, and may exchange a CI job's OIDC token
through `SPOTLIGHT_OIDC_TRUST` instead. Its subcommands, flags, output and
exit codes are on [`spotlight replay`](/docs/reference/cli/replay-command).
