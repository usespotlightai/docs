The `spotlight_workspace_token_trust` resource, and the API's
`workspace-token-trust` kind: a trust that lets a CI workload exchange the OIDC
token its platform issues for a short-lived
[workspace token](/docs/reference/api/workspace-token).

| Kind | Endpoint | Terraform | Address |
| --- | --- | --- | --- |
| `workspace-token-trust` | `/api/resources/workspaces/{workspaceId}/token-trusts` | `spotlight_workspace_token_trust` | `<key>` |

See [Resource API](/docs/reference/api/resource-api) for the operations, headers
and errors every kind shares.

## Example

```hcl
resource "spotlight_workspace_token_trust" "github_main" {
  workspace_id = spotlight_workspace.acme.id
  key          = "github-main"
  issuer       = "https://token.actions.githubusercontent.com"
  subject      = "repo:acme/platform:ref:refs/heads/main"
  claims = {
    repository_owner = "acme"
  }
  scopes           = ["configure", "secrets"]
  lifetime_minutes = 15
}
```

## Fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | string | required | Lowercase words joined by dashes, at most 64 characters. Immutable: an update that changes it is rejected; Terraform replaces the resource. |
| `issuer` | string | required | The issuer the workload's token must name in `iss`. `https`, or `http` only for `localhost`, `127.0.0.1` or `[::1]`. No query, fragment or credentials. At most 255 characters. |
| `audience` | string | `spotlight` | A value the token's `aud` must contain. One word, at most 255 characters. |
| `subject` | string | required | A pattern the token's `sub` must match. See [patterns](#patterns). |
| `claims` | map of name to string | `{}` | Further claims the token must carry, each matching its pattern. At most 16. See [patterns](#patterns). |
| `scopes` | array of strings | required | The scopes of every token the trust issues, as for a [workspace token](/docs/reference/api/workspace-token#scopes). |
| `lifetimeMinutes` | integer | `15` | 1 to 60. How many minutes an issued token stays valid. |
| `createdBy` | string | read-only | The person who created the trust, or who issued the token that created it. |

## Patterns

`subject` and each value of `claims` is one word of at most 255 characters,
with no whitespace. `*` matches any run of characters, colons included.

A `subject` with a `*` must name its owner before the first `*`: the text
before it must contain `/`.

| `subject` | Accepted |
| --- | --- |
| `repo:acme/platform:ref:refs/heads/main` | yes |
| `repo:acme/platform:*` | yes |
| `repo:acme/*` | yes |
| `repo:*` | no |
| `*` | no |

A rejected subject reads `must name an owner before any *, as in repo:acme/* or repo:acme/platform:*`.

Claim names are lowercase letters, digits and `_`, starting with a letter, at
most 64 characters. `iss`, `sub`, `aud`, `exp`, `nbf`, `iat` and `jti` may not
be named. Only claims whose value is a string can match.

## Platform subjects

| Platform | Issuer | `sub` |
| --- | --- | --- |
| GitHub Actions, pull request | `https://token.actions.githubusercontent.com` | `repo:<owner>/<repository>:pull_request` |
| GitHub Actions, push | `https://token.actions.githubusercontent.com` | `repo:<owner>/<repository>:ref:refs/heads/<branch>` |
| GitHub Actions, environment | `https://token.actions.githubusercontent.com` | `repo:<owner>/<repository>:environment:<name>` |
| GitLab CI/CD | `https://gitlab.com`, or the instance's address | set by the platform |
| CircleCI | `https://oidc.circleci.com/org/<organization id>` | set by the platform |
| Buildkite | `https://agent.buildkite.com` | set by the platform |

## Who may create a trust

Writing a trust needs the `manage-token-trusts` permission. See
[Roles and permissions](/docs/reference/roles-and-permissions).

A token may create a trust only with scopes it has itself, may change a
trust only when it has both the trust's current scopes and the new ones, and
may delete a trust only when it has the trust's current scopes. Otherwise the
write or delete is forbidden with `403`, as for a caller without
`manage-token-trusts`. See [Permission titles](/docs/reference/errors-and-messages#permission-titles).
A person who is an owner or admin is not limited this way.

## Exchange

```text
POST /api/workspace-tokens/exchange
```

Needs no credentials. Takes an optional `Spotlight-Client` header.

| Field | Type | Description |
| --- | --- | --- |
| `trust` | string | The trust's `id`. |
| `token` | string | The OIDC token the platform issued the workload. |

### Workload token verification

The workload's token is verified against the keys the issuer publishes at
`<issuer>/.well-known/openid-configuration`. It must be signed with `RS256`,
`RS384`, `RS512`, `ES256`, `ES384` or `PS256`, carry `sub` and `exp`, and be
current within 30 seconds. A [runner trust](/docs/reference/terraform/runner-trust#authentication)
verifies a host's token the same way.

A `200` response:

| Field | Type | Description |
| --- | --- | --- |
| `token` | string | The workspace token, sent as `Authorization: Bearer <token>`. |
| `tokenId` | string | Its id. |
| `workspaceId` | string | The workspace it acts in. |
| `scopes` | array of strings | The trust's scopes. |
| `expiresAt` | string | An RFC 3339 time. After this time, Spotlight does not accept the token. |

Every failed exchange gets `401` with `Spotlight did not accept the exchange. Possible causes: an unknown trust, a token its issuer did not sign for the trust's audience, a workload the trust does not match, or a deleted workspace`.

Each exchange is recorded as a
[configuration change](/docs/reference/api/resource-api#configuration-changes): a
created workspace token, with the trust, the subject, the scopes and the
expiry.

## Issued tokens

- An issued token acts for the trust's `createdBy`, within the trust's scopes.
- It is not listed among the workspace's tokens.
- Any change to the trust's terms stops every token issued before the change.
- Deleting the trust stops every token it issued, from that moment.
