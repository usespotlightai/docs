The `spotlight_inference_endpoint` resource, and the inference endpoint
resource of the API: the OpenAI-compatible endpoint and the one model that a
workspace uses for change stacks, decisions, answer grading, memory drafts and
judges. A workspace has at most one. Terraform and the resource API write it.
The **Inference** page of the web app shows it to every member and changes
nothing; see
[Set the workspace inference endpoint](/docs/administration/set-the-workspace-inference-endpoint).

| Kind | Endpoint | Terraform | Address |
| --- | --- | --- | --- |
| `inference-endpoint` | `/api/v1/resources/workspaces/{workspaceId}/inference-endpoints` | `spotlight_inference_endpoint` | `<workspace slug>` |

See [Resource API](/docs/reference/api/resource-api) for the operations, headers
and errors every kind shares.

## Example

```hcl
resource "spotlight_inference_endpoint" "acme" {
  workspace_id = spotlight_workspace.acme.id
  base_url     = "https://api.openai.com/v1"
  model        = "gpt-5-mini"

  api_key_wo         = var.inference_api_key
  api_key_wo_version = 1
}
```

## Fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `base_url` | string | required | The base URL of an API that accepts OpenAI Chat Completions requests at `/chat/completions`. |
| `model` | string | required | The model, as the endpoint names it. |
| `api_key_wo` | string | none | Write-only and sensitive. The API key. Set only with `api_key_wo_version`. |
| `api_key_wo_version` | number | none | Set only with `api_key_wo`. A change, with a new `api_key_wo`, rotates the key. |
| `api_key_set` | bool | read-only | Whether a key is stored. |

`api_key_wo` is write-only and needs Terraform 1.11 or later.

## The key

Spotlight stores the key encrypted, as the reserved built-in
[secret](/docs/reference/terraform/secret) `SPOTLIGHT_INFERENCE_API_KEY`. The
secrets list does not show it. No read, list or export returns the key.

Spotlight stores a key exactly when it stores a key version:

| Write | Result |
| --- | --- |
| `api_key_wo` and `api_key_wo_version`, on create | Stores the key. |
| `api_key_wo` without `api_key_wo_version`, or the reverse | Refused. The provider refuses it at plan. |
| A changed `api_key_wo_version` with `api_key_wo` | Stores the new key. |
| A changed `api_key_wo_version` without `api_key_wo` | Refused. |
| The same `api_key_wo_version`, with or without `api_key_wo` | Keeps the stored key. A key sent with it is ignored. |
| Neither, where a key is stored | Removes the stored key. Spotlight then calls the endpoint without an `Authorization` header. |

When `base_url` changes and a key is stored, the same write must send
`api_key_wo` and a changed `api_key_wo_version`. Spotlight never sends the
stored key to a new address.

## Token scope

A token needs the `secrets` scope to change or test the endpoint.

## Test request

After each create and update, Spotlight sends one test request to the endpoint,
with the stored key. A failed test request does not undo the write. The
response then carries a warning at the root of the resource, with severity
`warning`:

```text
The test request to the endpoint failed. Spotlight saved the change. <cause>
```

Terraform shows it as a warning, and the apply succeeds.

To test an endpoint without saving it:

```text
POST /api/v1/resources/workspaces/{workspaceId}/inference-endpoint/test
```

The body has the fields of a create. It answers `{ "ok", "message" }`: whether
the endpoint answered a minimal request, and what happened. It saves nothing.
Without `apiKeyWo`, it sends the stored key, and only to the stored base URL.

## Requests

Requests go through the workspace's egress rules. A private or loopback host
works only where the deployment already allows it.

Spotlight finds out from the first request whether the model accepts
`reasoning_effort`. It sends the field, and if the endpoint answers `400` or
`422`, it sends the request again once without it. Spotlight keeps the result in
memory and leaves the field out of later requests to the endpoint. After a
change to the endpoint, or a restart of the control plane, it finds out again.

## Import

Import it by the slug of its workspace:

```hcl
import {
  to = spotlight_inference_endpoint.acme
  id = "<workspace id>/acme"
}
```

## Export

The [workspace export](/docs/reference/api/resource-api#export) writes the
endpoint to `inference.tf`, with its `import` block in `imports.tf`. When a key
is stored, `api_key_wo` reads `var.inference_api_key`, a sensitive variable in
`variables.tf`, and `api_key_wo_version` is the version the API reports. The
export never contains the key.

## Delete

Deleting it removes the endpoint and its key. Change stacks, decisions, answer
grading, memory drafts and judges are then off for the workspace.
