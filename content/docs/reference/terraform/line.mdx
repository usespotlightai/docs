The `spotlight_line` resource, and the line resource of the API: a team's
workflow, made of its stations, the reactions that move tasks between them, and
the repositories its runs work in.

| Kind | Endpoint | Terraform | Address |
| --- | --- | --- | --- |
| `line` | `/api/resources/teams/{teamId}/lines` | `spotlight_line` | `<team key>/<key>` |

The request body is the line definition. A read returns `teamId`, `key` and
`definition`, the definition with every default filled in, beside the
[common fields](/docs/reference/api/resource-api#common-fields). See
[Built-in lines](/docs/reference/built-ins/built-in-lines) for the lines Spotlight opens
for the first team of a workspace created in the web app.

In Terraform, each element of `repositories`, `stations` and `reactions` is a
`repository`, `station` or `reaction` block, and `reviews` is a `reviews`
block.

## Example

```hcl
resource "spotlight_line" "core_delivery" {
  team_id = spotlight_team.core.id
  key     = "delivery"
  name    = "Delivery"
  role    = "delivery"
  runners = ["vpc-internal"]

  repository {
    name  = "acme/api"
    image = "ghcr.io/acme/api-runner:main"
    setup = "npm ci"
  }

  station {
    key       = "backlog"
    name      = "Backlog"
    kind      = "backlog"
    passes_to = ["implementation"]
  }

  station {
    key       = "implementation"
    name      = "Implementation"
    harness   = "claude-code"
    profile   = spotlight_harness_profile.core_careful.key
    prompt    = file("${path.module}/prompts/core/delivery/implementation.md")
    check     = "npm test"
    diffs     = true
    decisions = true
    memories  = true
    tools     = ["${spotlight_integration.core_acme.source}.comment", "pull-request"]
    skills    = [spotlight_skill.core_grafana.key]
    runners   = ["gpu"]
    passes_to = ["code-review"]
  }

  station {
    key       = "code-review"
    name      = "Code review"
    harness   = "claude-code"
    passes_to = ["implementation"]
    ends      = true
  }

  station {
    key  = "completed"
    name = "Completed"
    kind = "completed"
  }

  reaction {
    happening = "github.checks.failed"
    from      = "implementation"
    to        = "implementation"
  }
}
```

A `reviews` block, on a line whose `role` is `review`:

```hcl
reviews {
  start   = "opened"
  mention = "@spotlight"

  skip {
    spotlight = true
    drafts    = true
    authors   = ["dependabot[bot]", "renovate[bot]"]
  }
}
```

## Line fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | string | required | Names the line within its team. Lowercase words joined by dashes, at most 64 characters. Fixed: an update that changes it is refused; Terraform replaces the resource. |
| `name` | string | required | What the line is called. At most 100 characters. |
| `role` | string | none | The role the line plays for its team, as in `delivery` or `review`. Lowercase words joined by dashes, at most 64 characters. A role names one line per team. |
| `repositories` | array of objects | `[]` | The repositories the line works on. See [repositories](#repository-fields). |
| `stations` | array of objects | required | The stations, in order. At least one. See [stations](#station-fields). |
| `reactions` | array of objects | `[]` | Moves a task when something happens. See [reactions](#reaction-fields). |
| `reviews` | object | none | The review policy: which pull requests the line reviews. Only on a line whose `role` is `review`. See [review policy fields](#reviews-fields). |
| `runners` | array of strings | `[]` | Runner labels the line's work is placed on. Empty: any runner of the workspace qualifies. See [placement](#placement). |

## Station fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | string | required | Names the station within the line, and is what a run hands a task on to. Lowercase words joined by dashes, at most 64 characters. Not `review` or `done`. |
| `name` | string | required | What the station is called on the board. At most 100 characters. |
| `kind` | string | `work` | `backlog`, `work` or `completed`. |
| `color` | string | `#a3a8b0` | A six-digit hex colour, as in `#6d78d5`. Stored in lower case. |
| `description` | string | none | What the station is for. At most 500 characters. |
| `harness` | string | none | The [harness](/docs/reference/hosts/harnesses) that works tasks here: `claude-code`, `cursor` or `codex`. At most 60 characters. A station without one runs nothing, and no run may hand a task on to it. |
| `model` | string | none | The model the harness uses. At most 60 characters. Without it, the harness uses its own default. |
| `effort` | string | none | `low`, `medium`, `high`, `xhigh` or `max`. Without it, the harness uses its own default. |
| `profile` | string | none | The key of a team [harness profile](/docs/reference/terraform/harness-profile). A run at a station naming a profile the team does not hold is refused. |
| `prompt` | string | none | Markdown handed to the agent that works the station. At most 20,000 characters. |
| `check` | string | none | A command each layer of a change stack drafted at this station is checked with, as in `npm test`. One line of at most 500 characters. See [checks](/docs/reference/app/change-stacks-and-decisions#checks). |
| `runners` | array of strings | none | Runner labels this station's work is placed on. Without it, the line's `runners` apply. See [placement](#placement). |
| `diffs` | boolean | `false` | Whether a change stack is drafted from each run's diff. See [Change stacks and decisions](/docs/reference/app/change-stacks-and-decisions). |
| `decisions` | boolean | `false` | Whether decisions are drafted from each run. See [decisions](/docs/reference/app/change-stacks-and-decisions#decisions). |
| `memories` | boolean | `false` | Whether proposed team memories are drafted from each completed run, for the team to approve in the inbox. They come from what the agent said, thought and planned, never tool output, and from what people said on the task since the last draft. See [memory](/docs/reference/glossary#memory). |
| `tools` | array of strings | `[]` | The tools given to the agent. See [tool names](#tool-names). Each tool once. |
| `skills` | array of strings | `[]` | The skills given to the agent: a team [skill](/docs/reference/terraform/skill) key, or a catalog skill as `catalog.<name>@<x.y.z>`. Each skill once. A key starting `spotlight-` is refused. |
| `passesTo` | array of strings | `[]` | The keys of the stations a run here may hand a task on to. |
| `ends` | boolean | `false` | Whether a run here may finish the task by handing over with `done`. From any other station, `done` goes to a person instead. |

Spotlight checks catalog tools and skills against what the workspace's plan
includes when the line is written. It does not check at write time that a
`harness` exists or that a `profile`, a team skill or an integration tool is
there.

### Tool names

| Form | Example | Tool |
| --- | --- | --- |
| a built-in name | `pull-request`, `review-comment`, `review` | Spotlight's own. |
| `<integration>.<tool>` | `acme.comment` | A tool an [integration](/docs/reference/terraform/integration) of the team offers. |
| `catalog.<name>@<x.y.z>` | `catalog.web-search@1.1.0` | A catalog tool at an exact version. |

See [Built-in tools and skills](/docs/reference/built-ins/built-in-tools-and-skills) for
the built-in and catalog tools, and
[Agent commands](/docs/reference/cli/agent-commands) for how an agent calls a tool.

## Repository fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | string | required | `owner/name`. Each repository once per line. |
| `image` | string | none | The runner image every station of the line runs in, as in `ghcr.io/acme/api-runner:main`. Without it, the host's default image. Lower case except the tag, at most 255 characters, with an optional tag or `@sha256:` digest. The image is built `FROM ghcr.io/usespotlightai/spotlight-runner`. |
| `setup` | string | none | A command run in the checkout, as the agent, before each run's agent starts, and before a change stack check wherever a layer changes a lockfile. One line of at most 500 characters. |

The repositories of one line name at most one distinct `image`. A read returns
repositories sorted by name.

## Reaction fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `happening` | string | required | What happens, source first, as in `github.checks.failed`. Matches `^[a-z0-9]+(\.[a-z0-9][a-z0-9_-]*)+$`. |
| `from` | string | none | The key of the station the task must stand at for the reaction to apply. Without it, the reaction applies at any station. |
| `to` | string | required | The key of the station the task moves to. While a run holds the task, the move waits until the run ends, and is dropped if the run passes the task on. A move to the completed station instead stops the run and asks a person, or, if the task awaits an answer to the run's question, adds a note to it. See [Moves](/docs/reference/app/tasks-runs-and-the-inbox#moves). |

See [GitHub events](/docs/reference/events/github-events) for the happenings GitHub
raises. An [integration](/docs/reference/terraform/integration) raises its own.

## Review policy fields [#reviews-fields]

The review policy (`reviews`) decides which pull requests a review line takes.
See [Review tasks](/docs/reference/events/github-events#review-tasks) for how a line
is chosen and the task it opens.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `start` | string | `mentioned` | `mentioned`: take a pull request when the `mention` handle appears in a comment or review on it. `opened`: also take every pull request as it opens. |
| `mention` | string | `@spotlight` | The handle that asks for a review. Matches `^@[A-Za-z0-9][A-Za-z0-9_-]*(\[bot\])?$`. Matched as a whole word, without regard to case. |
| `skip.spotlight` | boolean | `true` | Skip pull requests Spotlight opened: a head branch under `spotlight/`, or a pull request a task opened. |
| `skip.drafts` | boolean | `true` | Skip draft pull requests when they open. A mention on a draft is still taken. |
| `skip.authors` | array of strings | `[]` | GitHub logins whose pull requests are skipped, as in `dependabot[bot]`. Compared, stored and sorted in lower case, each once. |

## Placement

A run at a station goes to a runner that carries at least one of the station's
`runners` labels. A station's `runners`, when set, are the only labels that
apply. A station without `runners` uses the line's. With neither, any runner of
the workspace qualifies.

A label is one a [runner pool](/docs/reference/terraform/runner-pool) or [runner trust](/docs/reference/terraform/runner-trust)
gives the runners it admits. A pool's `key` is not a label. Each entry is
shaped as a label is, lowercase words joined by dashes of at most 64
characters, and named once; any other entry is refused.

Where the line's repositories name an `image`, the runner must also run that
image. Where they name none, the runner must run its host's default image.
See [Host settings](/docs/reference/hosts/host-configuration#sandboxes) for the
images a host serves.

## Layout rules

A line's stations are refused unless they follow every rule below.

- A line must have at least one station.
- Each station key must be used once.
- A line must have exactly one `backlog` station, and it must be first.
- A line must have exactly one `completed` station, and it must be last.
- The `completed` station must not pass to any station.
- A station must not pass to itself.
- A station must pass only to `work` stations.
- A reaction's `to` and `from` must be stations on the line.
- A line must not have two reactions with the same `happening` and `from`.
- If any station has both `check` and `diffs: true`, every repository must have
  `setup`.
- A line must name `reviews` only if its `role` is `review`.

## Reserved station keys

| Key | A run that hands over to it |
| --- | --- |
| `review` | hands its task over to a person |
| `done` | finishes its task |

## Update and delete

| Operation | Behaviour |
| --- | --- |
| update | Replaces the whole definition. A station whose key is kept keeps its identity and the tasks at it. Changing `key` is refused with `422`. Dropping a station where any task stands is refused with `409` `in-use`, naming the stations and how many tasks stand at each. |
| delete | Refused with `409` `in-use` while any task stands on the line. |

A second line claiming a role another line of the team holds is refused with
`422` on `role`.
