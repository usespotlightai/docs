The `spotlight_secret` resource, and the secret resource of the API: a
workspace's credential that Spotlight puts in a request header on requests to
the hosts it is bound to. Its value never enters a sandbox.

| Kind | Endpoint | Terraform | Address |
| --- | --- | --- | --- |
| `secret` | `/api/resources/workspaces/{workspaceId}/secrets` | `spotlight_secret` | `<name>` |

See [Resource API](/docs/reference/api/resource-api) for the operations, headers
and errors every kind shares.

## Example

```hcl
resource "spotlight_secret" "acme_api_key" {
  workspace_id = spotlight_workspace.acme.id
  name         = "ACME_API_KEY"
  bindings = [
    { host = "api.acme.example", prefix = "Bearer " },
  ]
  value_wo         = var.secret_acme_api_key
  value_wo_version = 1
}

resource "spotlight_secret" "acme_signing" {
  workspace_id = spotlight_workspace.acme.id
  name         = "ACME_SIGNING"
  source = {
    kind      = "aws-secrets-manager"
    secret_id = "acme/signing"
    field     = "secret"
  }
}
```

## Fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | string | required | Capitals, digits and `_`, starting with a capital, at most 64 characters. Fixed: an update that changes it is refused; Terraform replaces the resource. |
| `source.kind` | string | `built-in` | `built-in` or `aws-secrets-manager`. Where the value lives. |
| `source.secretId` | string | none | For `aws-secrets-manager`: the secret's name or ARN, 1 to 2,048 of `A-Z a-z 0-9 / _ + = . @ : -`. |
| `source.field` | string | none | For `aws-secrets-manager`: one key of the JSON the secret holds. No whitespace, at most 256 characters. |
| `bindings` | array of objects | `[]` | The hosts the secret is sent to. At most 32, each host once. |
| `valueWo` | string | none | Write-only. The value, for `built-in`. Not empty, at most 64 KiB. |
| `valueWoVersion` | integer | none | At least `0`. A change, with a new `valueWo`, rotates the value. |
| `rotatedAt` | string | read-only | When the value was last set, as an RFC 3339 time. |

In Terraform, `value_wo` is write-only and needs Terraform 1.11 or later.

## Sources

| `source.kind` | Value |
| --- | --- |
| `built-in` | Kept by Spotlight, sealed. `valueWo` is required on create, whenever `valueWoVersion` changes, and when a secret moves to `built-in` from another source. |
| `aws-secrets-manager` | Read from AWS Secrets Manager when the secret is used. `valueWo` is refused: `is kept only by Spotlight; a secret read from AWS Secrets Manager is set there`. |

For a run, a secret from AWS Secrets Manager is read by
[egress](/docs/reference/hosts/egress) with the host's own AWS identity, among the
names `SPOTLIGHT_EGRESS_READS` allows; see
[Host settings](/docs/reference/hosts/host-configuration#egress). For an
integration request made by Spotlight, it is read only when the deployment
reads from AWS Secrets Manager; otherwise the request fails with
`The <NAME> secret could not be read: this deployment does not read from AWS Secrets Manager`.

## Bindings

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `host` | string | required | One hostname of at least two labels, lowercased, with no scheme, port or path, as in `api.acme.example`. |
| `header` | string | `authorization` | The request header the value is put in, lowercased, at most 128 characters. |
| `prefix` | string | `""` | Up to 64 printable ASCII characters written before the value, as in `Bearer `. |

The header may not be `host`, `content-length`, `content-type`,
`transfer-encoding`, `connection`, `upgrade`, `te` or `trailer`.

A secret is sent only over HTTPS, and only to a hostname equal to a bound
`host`. A request to any other address goes without it. A value of more than
one line cannot be sent: `The <NAME> secret holds more than one line, so it cannot be worn in a request header`.

## Where a secret is named

A secret is named as `secret.<NAME>`.

| Where | Field | Checked when written |
| --- | --- | --- |
| [Integration](/docs/reference/terraform/integration) | `webhook.verify.hmac.secret` | no |
| Integration | `webhook.verify.token.secret` | no |
| Integration | a request's `auth.secrets` | no |
| Integration | `connection.manual.secrets` | no |
| [Harness profile](/docs/reference/terraform/harness-profile) | `mcpServers[].env` values | yes |

A secret that is named but not defined fails where it is used, with
`The workspace holds no secret named <NAME>; define it before anything uses it`.
A [skill](/docs/reference/terraform/skill) declares the secrets it needs in the
`secrets` of its `SKILL.md`, by name only.

No expression may read a secret's value. See
[Evaluation](/docs/reference/api/expressions#evaluation).

## Rules

- Writing a secret needs the `manage-secrets` permission. See
  [Roles and permissions](/docs/reference/roles-and-permissions).
- A secret still named by an integration or a harness profile cannot be
  deleted. The delete is refused with `409` and `The <NAME> secret is still worn by <names>; stop those naming it first`.
- No read, list, import, export or
  [configuration change](/docs/reference/api/resource-api#configuration-changes)
  holds the value. A configuration change records the value version and the
  bound hosts.
- A secret belongs to the workspace, and every team in it can name it.
