Every part of [replays](/docs/reference/app/replays) other than candidates is
read and changed through these endpoints, under `/api/teams/{teamId}`.
Searches have the [Searches API](/docs/reference/api/searches), and checks of
planned changes the [Replay checks API](/docs/reference/api/replay-checks). They
answer JSON, and errors are `application/problem+json` as on the
[resource API](/docs/reference/api/resource-api#errors). Candidates are the
[`replay-candidate`](/docs/reference/api/replay-candidate) resource. The
team's replayed candidates over a period, beside each set's baseline, are read
through the [Replayed candidates API](/docs/reference/api/replayed-candidates).

`{lineId}` is a line's id, and `{stationId}` a station's id, as a candidate's
`stationId` contains it.

## Endpoints

| Method and path | Returns |
| --- | --- |
| `GET /lines/{lineId}/stations/{stationId}/replay-sets` | The station's replay sets, each with its runs, whether each can still be replayed, `guardsChanges`, whether the set [guards the station's changes](/docs/reference/api/replay-checks), its [`health` and `minGain`](#set-health), and its [`composition`](#set-composition). |
| `GET /replay-sets` | Every replay set of the team, including those whose station has left its line. With `line` and `station`, only one station's. |
| `GET /lines/{lineId}/stations/{stationId}/replayable-runs` | The station's latest 50 ended task runs, newest first, each with its `unreplayableReason` and `reason`, or none. |
| `GET /replay-sets/{setId}/suggestions` | Up to 5 of the station's recent runs that would even out how the set's runs turned out, each as `replayable-runs` lists it, with its `outcome`. None is added. See [Suggested runs](/docs/reference/app/replays#suggested-runs). |
| `POST /lines/{lineId}/stations/{stationId}/replay-sets` | `201` and `{ "id" }`: opens an empty set. |
| `PATCH /replay-sets/{setId}` | `204`: renames the set, also once its station has left its line. |
| `DELETE /replay-sets/{setId}` | `204`: deletes the set and its replays, and releases the archives it holds. |
| `POST /replay-sets/{setId}/entries` | `204`: adds a run to the set. |
| `DELETE /replay-sets/{setId}/entries/{runId}` | `204`: takes a run out of the set, also once its station has left its line. |
| `GET /replay-sets/{setId}/replays` | Every replay of the set, newest first, with each run's result, the baseline marked. |
| `POST /replay-sets/{setId}/replays` | `201`: starts a replay. See [Start a replay](#start-a-replay). |
| `GET /replays/{replayId}` | One replay, its totals, its baseline's id, the [counterpart](/docs/reference/app/replays#counterparts) it is compared with in `comparedWith`, its gain over that replay, and each task against it, regressions first. A replay a search started carries `search`: `{ searchId, candidateName }`, with `seed` for the live config; otherwise `search` is null. |
| `POST /replays/{replayId}/stop` | `204`: stops the replay. |
| `GET /replay-runs/{runId}/replay` | The replay a replay run belongs to, its candidate and set, `search` as above, and the run's result in it. |
| `GET /replay-runs/{runId}` | A replay run: the run it replays, its steps, and what it spent. |

`GET /replay-sets` takes:

| Parameter | Description |
| --- | --- |
| `line` | With `station`: the id of the line whose station's sets to list. |
| `station` | With `line`: the key of the station whose sets to list. A line the caller cannot see, or a key the line has no station by, is answered `404`: `Station <key> not found.` |

## Request bodies

| Endpoint | Body |
| --- | --- |
| Open or rename a set | `{ "name": "<name>" }`. 1 to 100 characters, with surrounding spaces trimmed. |
| Add a run | `{ "runId": "<run id>" }`. An ended task run at the set's station. |
| Start a replay | `{ "candidate": "<candidate id or live>", "ceiling": { "amount": <number>, "currency": "<code>" }, "repeats": <number> }`. `repeats` may be left out. |

## Start a replay

`candidate` is the id of one of the station's proposed candidates, or `live`
for the station as it is configured now. `ceiling.amount` is above 0 and at
most 1,000, and `ceiling.currency` a three-letter code. `repeats` is how many
times to replay each run, 1 to 5, and `1` when left out; `ceiling` covers every
copy.

When the set has no baseline covering all its runs with at least `repeats`
copies of each, a baseline replay of the live config starts too, with a
ceiling of its own equal to `ceiling` and the same `repeats`. With
`candidate` set to `live`, the replay itself becomes the baseline.

That baseline, either one, also [checks the set](#checking-the-set) when the
set contains 5 runs or more and no replay of the live config at its current
config fingerprint over the whole set has checked it while queued, running or
finished. It then replays each run `max(repeats, 3)` times, under a ceiling
of `ceiling` times those repeats divided by `repeats`, at most `1,000`. The answer:

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | The replay. |
| `ceiling` | object | `{ amount, currency }`, the replay's own ceiling, raised when the replay is a baseline that checks the set. |
| `baseline` | object or null | `{ id, ceiling, status }` when a baseline started, `ceiling` raised when it checks the set: `status` is `started` when the replay is the baseline, and `starting` when a baseline starts beside it. Null when the set's baseline already covers its runs. |

## Checking the set

No endpoint starts a check. A baseline checks the set as described under
[Start a replay](#start-a-replay); a search's replay of the live config and a
[replay check](/docs/reference/api/replay-checks)'s baseline never do. A set of
fewer than 5 runs is never checked. Once the checking baseline finishes, each
change whose check passed or failed is checked a second time, and each change
the judge gave a verdict on is judged a second time, in order, while the
ceiling still has room for one more at what its first judging cost. The
second judgings count against the ceiling, but not in the replay's
success or `costPerRun`. Neither changes a run's result. See
[Checking the set](/docs/reference/app/replays#checking-the-set).

## Success, ranges and noise

A replay read carries:

| Field | Type | Description |
| --- | --- | --- |
| `repeats` | number | How many times it replays each run of its set. |
| `totals.successRate` | number or null | Its [success](/docs/reference/app/replays#success), 0 to 1: per task, the share of its scored copies that succeeded, averaged over the tasks scored. |
| `totals.interval` | object or null | `{ rate, low, high }`: the success rate and its 95% interval, bootstrapped over the tasks. Null while none was scored. |
| `totals.tasks`, `totals.tasksScored` | number | How many tasks it replays, and how many have a scored copy. `entries`, `ended`, `scored` and `unscored` count copies. |
| `againstBaseline` | object or null | Its [gain](#gain) over the replay in `comparedWith`, with whether it is within noise. Null where `comparedWith` is, and while no task was scored on both sides. |
| `comparedWith` | object or null | `{ replayId, successRate, interval }`: the replay its gain, `comparison` rows and deltas are against, with its success. Null for the baseline itself, or with none. See [Compared with](#compared-with). |
| `entries[].repeat` | number | Which copy of its original run an entry is, from 1. |
| `comparison` | array | On a single replay's read: one row per task against the replay in `comparedWith`, regressions first. |
| `comparison[].candidate`, `comparison[].baseline` | array | Each copy of the task this replay, and the replay in `comparedWith`, replayed. `baseline` is empty without one. |
| `comparison[].candidateSuccess`, `comparison[].baselineSuccess` | number or null | The share of each side's scored copies that succeeded. |
| `comparison[].costDelta`, `msDelta`, `stepsDelta` | number or null | This replay's measure less that of the replay in `comparedWith`, each averaged over its copies, once every copy of both has ended. |
| `comparison[].regressed` | boolean | See [Regressions](/docs/reference/app/replays#regressions). |
| `probe` | boolean | Whether it [checks the set](#checking-the-set). |
| `entries[].secondJudge` | object or null | A check's second judging of the entry's change, in the shape of its first. Null when it was not judged again. |
| `entries[].rejudgingSpent` | object or null | What the second judging cost. |
| `entries[].recheck` | object or null | A check's second check of the entry's change, in the shape of its first. Null when it was not checked again. |

A replay read also carries, as in [Judge verdicts](#judge-verdicts) and
[Side by side](#side-by-side), each entry's `judge`, `pair` and
`pairingSpent`, and the replay's `pairedWith` and `pairsAgainstBaseline`.

### Compared with

Each replay on the list of a set's replays, and a single replay's read, carry
`comparedWith`.

| Field | Type | Description |
| --- | --- | --- |
| `replayId` | string | The replay compared with: `pairedWith` where set, else for a [replay with the answer](/docs/reference/app/replays#replay-with-the-answer) the live replay whose finishing started it, else the set's baseline. |
| `successRate` | number or null | Its success on the tasks the gain pairs, the tasks both replays scored: per task, the share of its scored copies that succeeded, averaged over those tasks. Null with no such task. |
| `interval` | object or null | `{ rate, low, high }`: that success rate and its 95% interval over those tasks. Null with no such task. |

`comparedWith` is null for the set's baseline, for a replay that keeps no
counterpart while the set has no baseline, and for a replay whose counterpart
is gone, such as a replay with the answer whose live replay is gone. See [Counterparts](/docs/reference/app/replays#counterparts).

### Judge verdicts

An entry's `judge`:

| Field | Type | Description |
| --- | --- | --- |
| `scale` | string or null | `yes-no`, `number` or `claims`. |
| `score` | number or null | 0 or 1 on `yes-no`, 1 to 5 on `number`, or the share of claims met on `claims`. |
| `marks` | array of booleans or null | Whether each claim was met, in order. Null unless `scale` is `claims`. |
| `claims` | array of strings | The claims the judge marked, in order, as worded when it judged. Empty unless `scale` is `claims`. |
| `passShare` | number or null | The share of claims the run had to meet to pass. Null unless `scale` is `claims`. |
| `reasons` | array | The judge's reasons, each `{ text, claim, citations }`. `claim` is the place of the claim it is about, from 0, or null on a rubric's scale. Each citation is `{ kind, step, hunk }`, `kind` `step` or `hunk`; a step has its `index` and a hunk its `id`, and their other fields are null or empty, because a replay keeps no copy of what the judge read. |

### Side by side

See [Side by side](/docs/reference/app/replays#side-by-side).

| Field | Type | Description |
| --- | --- | --- |
| `pairedWith` | string or null | The replay its changes are set beside, judged blind, once it finishes, chosen when it started: the baseline that was current then, or its search's replay of the live config. It is then also its [counterpart](/docs/reference/app/replays#counterparts), in `comparedWith`. Null for a baseline, a check of the set, a replay with the answer, or a replay that had none. |
| `pairsAgainstBaseline` | object or null | `{ wins, losses, ties }`, counting tasks. Null where `pairedWith` is. |
| `entries[].pair` | object or null | `{ state, againstRunId, outcome, model, unpaired, readings }`. `state` is `requested`, `judged` or `unpaired`. `againstRunId` is the run of the same task in `pairedWith` it was set beside. `outcome` is `win`, `loss` or `tie` once judged. `unpaired` is the [reason](/docs/reference/app/replays#side-by-side) when not compared, including `other-rubric` and `budget`. `readings` contains the two readings, each `{ ownShownFirst, outcome, reasons }`, each reason `{ text, ownHunks, theirHunks }`, the hunks it cites of this change and of the other. Null until requested. |
| `entries[].pairingSpent` | object or null | What the side-by-side judging cost. It counts against the ceiling, but does not add to `totals.spent`. |
| `comparison[].pair` | string or null | `win`, `loss` or `tie` for the task, from most of its compared copies. Null when none was compared. |

A replay set read carries `health`, as in [Set health](#set-health), and
`minGain`, the smallest gain its line counts as real: `replay_check.min_gain`,
or `0.05` when the line has none.

### Gain

| Field | Type | Description |
| --- | --- | --- |
| `gain` | number | The success rate gained, on the tasks both sides scored, paired task by task. |
| `low`, `high` | number | The 95% interval of the gain, a paired bootstrap over those tasks. |
| `verdict` | string | `better`, `worse` or `within-noise`. See [Gains](/docs/reference/app/replays#gains). |
| `minGain` | number | The smallest gain the line counts as real. |
| `tasks` | number | How many tasks both sides scored. |

## Set health

A set's `health` is read for the station's live config at its current
[config fingerprint](/docs/reference/glossary#config-fingerprint). See
[Health](/docs/reference/app/replays#health).

| Field | Type | Description |
| --- | --- | --- |
| `noise` | object or null | `{ replayId, fingerprint, repeats, perRepeat, spread, flippedTasks, measuredAt, noisyInOneCopy }`. `perRepeat` is each copy's success rate, in order; `spread` the highest less the lowest; `flippedTasks` the ids of tasks whose copies both succeeded and failed. `noisyInOneCopy` is true when one copy of each run cannot tell a gain of `minGain` from chance: when `spread` divided by `minGain`, squared and rounded up, is more than 1. Null until a finished replay of the live config replayed each run 2 or more times. |
| `saturation` | object or null | `{ replayId, rate, interval, saturated, measuredAt }`, from the newest finished replay of the live config over the whole set, outside a search. `saturated` is true when `rate` is above 0.95. Null until there is one. |
| `judge` | object or null | `{ replayId, compared, agreed, pending, agreement, unstable }`, from the newest finished [check of the set](#checking-the-set). `compared` counts changes judged twice, both times with a verdict; `agreed` those passed or failed alike both times; `pending` the second judgings still to come; `agreement` is `agreed` out of `compared`, or null before any is compared. `unstable` is true when `agreement` is below 0.8. Null until a check requested a second judging. |
| `checks` | object or null | `{ replayId, rechecked, pending, flaky }`, from the same check. `rechecked` counts changes checked twice, both times passing or failing; `pending` the second checks still to come; `flaky` lists each change whose check passed once and failed once, as `{ taskId, originalRunId, runId, first, recheck }`, `first` and `recheck` each `passed` or `failed`. Null until a check requested a second check. |
| `oracle` | object or null | `{ replayId, candidateId, repeats, state, againstReplayId, againstState, answered, live, withAnswer, gain, roomToImprove }`, from the newest [replay with the answer](/docs/reference/app/replays#replay-with-the-answer) of the live config as it is now: how much better the live config does when handed each run's answer. Spotlight starts it after a replay of the live config over the whole set finishes; it cannot be started through the API. `againstReplayId` is the live replay whose finishing started it, and `againstState` that replay's state, or `gone`: `finished` once the two can be compared, while `stopped`, `over-budget` or `gone` means they never will be. `answered` counts the runs it replayed, those whose original was accepted or sent back. `live` and `withAnswer` are the success of the live replay and of this one on those runs, and `gain` this one's [gain](#gain) over the live replay on them, the most a better config could gain there; each is null until both finished. `roomToImprove` is true when `gain` reads `better`, false when it does not, and null until compared or while fewer than 5 tasks were scored on both sides. Null until one started. |

## Set composition

A set's `composition` reads its original runs as they are when the set is
read. See [What a set is made of](/docs/reference/app/replays#what-a-set-is-made-of).

| Field | Type | Description |
| --- | --- | --- |
| `outcomes` | array | `{ outcome, count }` for each outcome, always all five, in the order `accepted`, `sent-back`, `asked`, `failed`, `other`. |
| `origins` | array | `{ origin, count }` for each origin, the largest count first, ties in alphabetical order. `origin` is `person`, `station`, an integration's name, or `unknown`. |
| `oldest` | string or null | When the set's oldest run ended. Null while no run's end can be read. |
| `median` | string or null | The median of when its runs ended. |
| `newest` | string or null | When its newest run ended. |
| `balanceWarning` | object or null | `{ dominant, count, entries }` when the set contains 6 runs or more and one outcome other than `other` covers more than two thirds of them. |

Each entry of the set also carries its run's `outcome`, one of the five above,
and `origin`, as in `origins` but null where `origins` reads `unknown`.

## Who may read and change

Reading needs a person on the team or an owner or admin of its workspace,
signed in, or a [workspace token](/docs/reference/api/workspace-token) of the
team's workspace with the `read` scope, sent as `Authorization: Bearer
<token>`. Anyone else is answered `404`. See
[Team outcomes](/docs/reference/roles-and-permissions#team-outcomes).

Opening, renaming and deleting sets, adding and removing runs, starting and
stopping replays also need `plan`: every person who may read, or a token
with `plan` or `configure`. A token with `read` alone gets `403`
and the title `Not allowed to plan`.

A replay run's config, at `GET /runs/{runId}/config`, is answered only to those who may read the team's replays.

Starting and stopping a replay are recorded as
[configuration changes](/docs/reference/api/resource-api#configuration-changes)
of the kind `replay`, keyed by the replay's id.

## Errors

| Status | Cause |
| --- | --- |
| `401` | No session or token, or an unknown token. |
| `403` | A change by a caller who may read the team but not plan. |
| `404` | The team, line, station, set, run, candidate or replay is not one the caller may see, as in `Replay set <setId> not found.` |
| `409` | Adding a run already in the set (`Run <runId> is already in the replay set.`), to a full set (`Replay set is full. Maximum runs: 50`), or that cannot be replayed (`Run <runId> cannot be replayed. <reason>`, with an [unreplayable reason](/docs/reference/app/replays#why-a-run-cannot-be-replayed)). Deleting a set while a replay or a search of it is under way, or adding or taking out a run while a search of it is under way (`Replay set <setId> is being replayed or searched. Please stop its replays and searches first.`). Adding a run to, or replaying, a set whose station has left its line (`The station of replay set <setId> is gone from its line. You can only rename the set, remove runs from it or delete it.`). Stopping a replay that has ended (`Replay <replayId> has already ended or been stopped.`). Starting a replay while the set's baseline changed (`The baseline of replay set <setId> changed while the replay was starting. Please start it again.`). |
| `422` | A missing or invalid field, at its path: a name out of length (`Replay set name must be 1 to 100 characters.`), a ceiling out of range (`Spend ceiling must be above 0 and at most 1,000.`) or not in a three-letter currency, `repeats` not a number (`Repeats must be a number.`) or out of range (`Replay repeats must be from 1 to 5.`), no `candidate` (`Candidate must be a candidate ID or "live".`), or a set with no runs (`Replay must replay at least one run.`). A run of another station (`Run <runId> worked at a different station from the replay set.`). `line` without `station`, or `station` without `line`, on `GET /replay-sets` (`Line and station must be sent together.`). |
